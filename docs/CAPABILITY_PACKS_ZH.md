# 两套能力包中文详解

## 总体边界

“智能软件工程平台”负责一般软件工程的长期规划、实现、协作、验证和发布；“桌面软件等价重建”负责已授权桌面软件从黑盒证据到等价交付的专项流程。前者可自动进入，后者必须明确选择。两者共享安全原则，但不共享项目状态、阶段门禁或任务事实源，防止上下文污染。

## 智能软件工程平台 5.18.0

### 入口与路由

“智能工程轻量路由”是唯一自动入口。简单问答直接走零脚本快速路径；普通项目已有充分证据时由ChatGPT选择最多两个原子Skill并一次守门，证据不足才先做一次轻量检查；多会话、合并、发布和长链路任务才进入完整治理。守门器不会通过关键词替代模型，也不会在拒绝后擅自换选。

五个插件必须具有同一完整版本。准入指纹绑定目标修订、源码身份、HEAD、脏状态、Manifest、阶段、动作和候选；命中后不重复读取Skill。旧任务检测到版本漂移时只允许保存Checkpoint和恢复迁移，由当前版本新任务接管后才能继续写源码。

### 从零项目与已有源码

从零项目先建立稳定需求 ID、冲突、未知项、验收条件和最多三个技术候选。已有源码先通过代码、测试和运行证据建立能力基线，再把需求对账为新增、修改、替换或移除。两条路径都禁止直接套固定脚手架覆盖用户需求。

用户提供的架构思路是待验证候选。AI 必须检查边界、状态、数据、接口、安全、可靠性、性能、部署、测试、演进和失败恢复，并按影响给出遗漏与替代方案；不为低风险小项目制造无用层级。

### 小型、大型与长寿命项目

小型项目读取当前任务、差异、直接契约和测试，保持低延迟。标准项目扩展到受影响模块和直接消费者。大型或长寿命项目从有界任务索引和变更分片进入，最多读取80个源码文件；超限必须继续切片，不能把全仓、所有归档和所有聊天塞进会话。

`.ai` 只保存可恢复的工程事实和派生状态。源码溯源使用仓库身份、HEAD、分支和 Manifest 哈希，不保存远程地址或本机绝对路径。发现漂移时：

- L1：刷新当前热状态和受影响索引；
- L2：重建受影响模块、技术和契约基线；
- L3：使旧候选、图谱、审核和测试证据失效；
- L4：隔离跨仓库或跨项目派生状态，重新建立身份。

需求、Task、决定和证据原件不会因为漂移被删除。

### 结构与实现唯一性

每个受治理 Task 有允许范围、行为不变量、公共表面、消费者和最低回归。公共模块与大文件不是到达行数后才机械拆分，而是在新增职责前检查模块边界、依赖方向和增长预算。

当同一功能多次修复、多个版本共存或迁移产生双入口时，登记受影响能力的实现清单。每个能力必须只有一个权威活动实现和一个权威状态写入者；兼容路径必须声明目标、退出条件和删除 Gate。废弃实现不得继续写状态或接收新增需求。普通局部任务没有这种风险时保持零配置。

### 多会话、多智能体与 Worktree

Master、Planning、Developer、Review、Test、Merge和Document角色按职责工作。只有总控能管理桌面任务和Worktree。实现/修复复用 writer 槽，审核/测试/复验复用 assurance 槽；Task、候选和基线变化只更新槽内工作，不创建新会话。

总控不再只按“前端/后端”固定拆分。ChatGPT 从当前变更契约、依赖和真实写范围提出动态所有权通道，适用于大型纯后端、多个前端、客户端模块和多仓库；规划态最多8个，运行态最多2个。父子目录、公共契约、迁移、共享状态或测试环境重叠时由守门器强制串行。

普通任务终态自动 Checkpoint、释放锁和任务资源并回到可复用状态。项目终态自动归档并核验本地运行时释放。查询失败、待启动、脏Worktree和回收未完成时禁止创建替代会话；其中查询失败不会冻结已有工作，不需要新隔离运行时的步骤在当前有界线程继续。自动回收不会强杀进程、强删目录或丢弃未提交改动。

长期总控按有效轮次、工具调用、输出字符和压缩次数分成有界纪元。达到阈值后先保存 Checkpoint，再建立唯一替代总控并归档旧运行时，不按每个步骤创建新会话。项目目标使用修订号和指纹绑定 Task；目标变化后旧 Task 必须显式重绑定。根上下文只保留总控摘要，每个活动 Task 使用独立上下文包，完整脱敏日志只写证据文件。

### 质量、用户体验与正式交付

界面从 B/S 或 C/S 项目事实进入语义 UI Design IR，记录业务任务、信息层级、阅读路径、状态、交互、Presentation 与验收；构图和视觉方向是可被用户覆盖的决策，不是固定模板。Design ↔ Code Component Registry、运行截图/等价客户端证据和 Fidelity 检查均绑定候选、目标修订与源码指纹，并只处理受影响范围。

Presentation Contract 区分技术标识与业务标识，Content Stress 依赖真实运行测量；Error Contract 兼容 REST、Problem Details、GraphQL、gRPC、C/S Local 与项目既有协议，用户安全消息、开发诊断和可反查 Error ID 分通道保留。下拉、菜单、弹窗、抽屉、快捷键、焦点、请求乱序和重复提交仍按当前模块进行有界交互检查。

风险与发布门禁检查正式运行路径：默认 Demo/Mock/Fixture、占位或样例身份、用户可见本机路径、堆栈和数据库内部错误都会阻断。审核只输出代码、路径和行号，不回显可能的敏感内容。

### 权限和透明度

自动应用不意味着自动 push、merge、部署、发布、生产写入或破坏性清理。软件工程会话第一条先显示中文轻量路由；实际 Skill 完整读取后再显示中文插件和中文 Skill 名称。工程健康发生重要变化时另行显示一次去重告警，说明问题、影响、措施和下一门禁。

## 桌面软件等价重建 1.3.0

### 使用范围

只处理已获授权的 Windows、macOS 或 Linux 桌面软件等价重建、迁移或替代。不得绕过许可证、登录、DRM，提取密钥，复制未授权源码、凭据或资产。黑盒观测只能记为外部行为证据，不能伪装成原软件内部实现事实。

### 五个 Skill 的关系

“桌面软件等价重建”只识别当前门禁并路由一个阶段 Skill。“桌面重建发现与规格”建立证据、功能、数据和交互规格；“桌面重建技术方案”比较候选并通过 POC 和官方资料锁定精确版本；“桌面重建实现”按规格和测试编号编码；“桌面重建验证与发布”独立做视觉、功能、数据、性能、稳定性、安装和交付验证。

### 性能与长期状态

每次只读取当前门禁状态、直接关联的参考、库存和证据索引。大型截图、录屏、二进制和历史证据先建索引再按编号取用。未通过门禁时停留在当前阶段，不同时加载发现、选型、实现和发布全部内容。

### 唯一性与交付洁净度

同一时刻只有一个当前交付候选。旧原型、失败方案和临时兼容层必须有状态、退出条件和清理 Gate，不得继续承载新增需求。正式交付不得默认启用 Demo/Mock/Fixture，不得包含占位数据、样例身份、本机路径、堆栈或数据库、设备内部诊断。

## 公开内容规则

两套能力包的源码、文档、模板、Eval、示例和发布压缩包都执行敏感信息审计：禁止个人、公司、真实项目、会话、凭据和本机路径；唯一允许的个人标识为 Hiker。项目运行时生成的信息只能留在对应项目目录，不得回写进通用能力包。
