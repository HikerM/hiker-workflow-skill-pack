# CHANGELOG

## 5.15.0

- 自动路由新增 `.ai` 三态策略：无 `.ai` 直接无状态轻量推进；一致状态才允许复用；无可信来源、仓库身份冲突或历史分叉的旧状态自动隔离，禁止恢复旧Task/旧PASS及创建多会话或Worktree。
- 最新用户请求与当前Git成为隔离模式下的唯一执行依据；普通设计、实现、审核和测试不再被过期治理状态拖入恢复循环。
- 修复 Windows 桌面运行时释放探针使用 `os.kill(pid, 0)` 进行存活检测的问题；Windows 现在通过只读进程句柄查询退出状态，不再干扰被探测进程。
- 新增动态实现所有权通道：ChatGPT可为B/S、C/S、纯后端、多仓库和模块化工程提出最多8个证据化通道；运行态最多激活2个，写范围父子重叠由派发守门器强制串行。
- 修复会话池把全部Developer折叠成单一writer的问题；writer槽身份增加稳定 `ownership_lane`，并兼容5.14旧状态键。
- 修复治理自锁：满足变更契约后，连续两个治理周期无业务增量时自动退出到Development并记录原因，不再停留在治理阶段。
- 新增项目目标契约、修订指纹、Task绑定与过期重绑定门禁，防止长时间总控偏离最新目标。
- 根 `CURRENT_CONTEXT.md` 改为总控有界摘要；每个Task使用独立上下文包，Task历史自动压缩归档，quick/status从活动索引读取。
- 新增总控会话纪元和有界命令执行：按轮次、工具调用、输出字符和压缩阈值轮换唯一总控，完整脱敏输出落盘，只向会话返回摘要与证据指针。
- 桌面任务查询失败时只禁止创建替代会话；不需要新隔离运行时的工作可在当前有界线程继续，确需隔离的步骤排队。
- 保持5个插件、42个原子Skill、唯一隐式入口和每阶段最多两个活跃原子Skill，不增加自动加载正文。

## 5.14.0

- 新增小型、标准、大型项目的动态上下文预算；长寿命项目从有界任务索引和受影响分片进入，不扫描全部历史、冷归档或Skill正文。
- 新增源码溯源与 `.ai` L1–L4 一致性恢复；Git、Manifest、锁文件和当前源码优先，修复只失效受影响派生状态，不删除需求、Task、决定和证据原件。
- 新增实现唯一性门禁；每个能力只能有一个权威活动实现和一个权威状态写入者，迁移必须声明目标、退出条件和删除 Gate。
- 风险与发布审核接入交付洁净度门禁，阻断正式运行路径中的默认 Demo、Mock、Fixture、占位身份和用户可见内部诊断。
- 插件作者与开发者标识统一为 Hiker；新增公开仓库、发布包和ZIP内部的敏感信息审计。
- 保持5个插件、42个原子Skill、唯一隐式入口和每阶段最多两个活跃原子Skill，不新增常驻上下文。

## 5.13.0

- 原子 Skill 选择权从关键词脚本迁回 ChatGPT：模型读取紧凑中文语义目录，结合当前动作、否定项、历史错误、未来计划和有界项目证据，提出最多两个当前候选及有界待执行队列。
- `suite_router.py` 改为确定性守门器，只校验候选存在性、数量、阶段兼容、Manifest/`.ai` 架构证据、源码身份和安全边界；没有模型提案时返回 `PROPOSAL_REQUIRED`，拒绝时不自动换选其他 Skill。
- 工作区大型任务路由同步改为模型提案协议：ChatGPT 选择架构与客户端技术族，`task_router.py` 只校验合法值并展开执行通道；移除第二套B/S、C/S、后端与客户端关键词分类，避免双重路由权威。
- 删除 `ACTION_TERMS`、`explicit_bs`、`explicit_cs`、插件关键词和分支优先选择链，修复“不是C/S”“禁止Android”“不要Worktree”“暂不merge”等否定表达触发错误能力的问题。
- 新增 `semantic-routing-catalog.md`、模型提案协议、目录覆盖审计、关键词路由回归禁令、阶段/架构冲突测试和无提案安全退化测试。
- Eval 现在明确区分 ChatGPT 原生语义选择与本地守门器验证；发布门禁覆盖五个插件全部42个 Skill，继续保持唯一隐式入口、最多两个活跃原子 Skill 和有界上下文预算。

## 5.12.0

- 架构与技术决策 Checkpoint 改为自动、非阻塞记录：平台、架构、部署、数据、安全、核心技术栈及公共契约变化记录候选、证据、风险、回退与选择后继续，不再弹出审批。
- 从零规划、存量需求对账、架构挑战、全局规则、使用文档和发布级一致性审计统一该语义；不可逆高影响操作、生产写入、部署、发布及外部权限仍遵守原安全门禁。
- 桌面任务和 Worktree 生命周期收归 Master Agent；执行角色不得自行创建替代会话或工作目录。
- 新增按项目、仓库与角色族定位的固定会话池：实现/修复复用 writer，审核/测试/复验复用 assurance，Task、Candidate 和 base SHA 只作为槽内工作项。
- 普通任务终态自动 Checkpoint、释放锁和任务资源并进入 `IDLE_REUSABLE`；项目终态自动归档并验证本地运行时释放，不要求人工确认。
- 默认限制每项目四个常驻角色槽和一个 pending create；API 错误、查询超时、待启动、脏 Worktree 或回收未完成时失败关闭。
- 新增会话池状态机、跨 Task/阶段复用、自动回收重试和路由识别测试；保持42个原子 Skill、唯一轻量隐式入口与最多两个活跃原子 Skill 的性能预算。

## 5.11.0

- 路由改为动作优先：增强、修复、实现、审核、测试、合并和发布按首次明确动作决定当前阶段，风险与验证词只作为限定或后续阶段。
- 应用回执改为加载遥测：只有实际完整读取且与活跃路由顺序完全一致的 Skill 才能显示“已应用”；阶段变化要求 Checkpoint 后重路由。
- 新增 `dispatch_guard.py`，区分桌面任务 API 错误、查询超时、明确空结果、延迟创建和真实运行；仅明确空结果允许创建，并在分派前生成环境预检计划。
- 新增不可变审核候选：Development→Review 前冻结 `candidate_id`，绑定提交、索引、源文件集合和工作区指纹；任意变化使旧 Review/Test/Merge 证据失效。
- 长链路增加根因假设账本；同一问题连续两个假设被否定后进入 `DIAGNOSIS_REQUIRED`，强制停止猜测式改码。
- 新增测试工具预检与敏感交接检查；大矩阵先校验运行时、目录、Windows 命令长度、计数、变异证据和正反样本，原始密码、令牌、私钥和带凭据 URL 阻断导出。
- 修复 Windows 中文 Git 输出使用系统编码导致的偶发解码失败；Marketplace 展示版本从长期滞留的5.6修正为5.11。

## 5.10.0

- 超长单会话和多轮上下文压缩新增持久 Skill 路由态：仅保存阶段、最多两个活跃原子 Skill、待执行 Skill 名称和路由指纹，不保存 Skill 正文。
- 明确两阶段中文回执：软件工程会话第一条助手输出先显示轻量路由；确定性路由后再显示实际活跃原子 Skill。轻量路由不计入两个原子 Skill 额度。
- 路由第三个及之后的匹配能力进入有界待执行队列，当前门禁完成后重新路由，修复原先达到两个能力后静默忽略后续能力的问题。
- `.ai` 改为热状态、有界索引与压缩冷归档：日常状态、任务创建和 Checkpoint 优先读取 `task-index.json`，旧 Checkpoint 压缩进 `.ai/archive/checkpoints/` 并记录哈希和精确索引，不扫描整个历史目录。
- 增加超长会话、回执自然语言、原子额度、待执行队列、路由态 Checkpoint 和冷归档恢复包自动测试。

## 5.9.0

- 新增中文原子 Skill「架构决策挑战与补全」：用户给出的系统架构、功能架构、模块拆分和技术方案只作为待验证假设，AI 必须保留真实目标，同时主动寻找反例、遗漏、隐性耦合、失败模式和演进风险。
- 架构挑战按边界、状态、数据、契约、安全、可靠性、性能成本、部署演进、测试运维九个视角排序，只深入会改变决策的高风险项；替代方案最多三个。该版本的阻塞式重大决策节点已在5.12改为自动、非阻塞决策记录。
- 从零需求融合、存量源码对账和设计就绪复审接入架构挑战，但职责仍然分离：挑战能力不直接编码、不覆盖能力基线、不冒充独立复审，也不为显得全面而无边界扩张。
- 新增 `audit_skill_coherence.py` 发布门禁，完整检查五个插件全部42个 Skill 的目录与登记、中文名称、职责类型、权限、手动提示、路由覆盖、正向 Eval、触发描述重叠、本地引用和上下文体积；普通项目路由不会运行全量审计。
- 修复多个手动 Skill 缺少默认提示、回执提示越界、职责登记曲解、描述过薄和合并能力授权边界不清等问题。路由 Eval 提升为92/92正向、38/38负向，仍保持唯一隐式入口和单轮最多两个原子 Skill。
- 从真实复杂总控会话抽象出治理收敛机制：业务价值进展与治理进展分离；连续两个治理空转周期后阻止无理由扩张；审批、任务、Gate 与证据采用单一事实源和派生视图，禁止多份全文投影互锁。
- `convergence_guard.py` 增加进展登记、验证计划与证据复用：相同 Gate、指纹和范围已有 PASS 时返回 `REUSE_PASS`，变化后只验证受影响切片；测试夹具或汇总器失败可记录为 `INVALID`，不再自动推翻未受影响的产品证据。
- 多会话调度增加延迟启动防重约束：`clientThreadId` 只进入 `SETUP_PENDING`，pending lease 未到期或尚未确认真实任务不存在时禁止创建恢复会话，避免同一 Worktree 出现重复 writer。

## 5.8.0

- 新增中文原子 Skill「长链路变更收敛」，通用于跨模块、多仓库、多轮修复、真实外部执行、部署回滚和用户纠正后的复杂工程任务，不包含任何具体项目、业务对象、模型或案例常量。
- 新增 `convergence_guard.py`：分离静态、集成、运行时、用户可见和生产证据；同一验收点连续两次真实失败后要求策略换轨，禁止继续叠加补丁或自动重试。
- 为每个业务职责登记唯一活动实现路径；迁移兼容路径必须带退出条件，合并前退役并提供删除或调用图不可达证据，阻止新旧代码和多个执行入口长期混用。
- 任务契约改变时自动提升验收修订并使旧证据待重新确认；功能闭环新增证据矛盾、未结实验、路径分叉、迁移未收敛和部署版本漂移门禁。
- 新增去重中文「工程状态告警」，仅在风险指纹变化时主动说明问题、影响、当前处置和下一门禁，不污染一行插件应用回执，也不重复输出完整日志。
- 轻量路由只通过有界关键词组合识别复杂链路；普通单文件或文案修改不加载本能力。路由 Eval 为 88/88 正向、36/36 负向。

## 5.7.0

- 新增无外部依赖的 `interaction_guard.py`：检查稳定交互 ID、状态可达性、异步并发策略、危险写入、浮层语义层级、快捷键冲突和非默认状态证据。
- 采用零配置不扫描、单模块显式契约、1 MiB/500交互/有界输出和线性图遍历；未命中交互冲突时不加载该 Skill，不增加普通消息的上下文负担。
- Web、通用客户端和 Unity 的设计、实现、审核阶段只增加轻量交接点，不复制治理正文、不创建万能 Store 或第二套全局事件系统。
- 路由新增精确交互冲突意图并保持单 Skill 命中；84 条正向与 34 条负向 Eval 全部通过。
- 修复 Skill 登记表遗漏「工作目录安全收敛」的问题，并由验证器强制登记表与实际目录双向一致。
- 发布打包器改为只保留当前五个可复现 ZIP，历史版本由 Git 历史或 Release 承载；验证器阻断发布目录再次累积旧包。

## 5.6.0

- 新增源码身份门禁：Git 仓库只使用当前 Worktree 的已跟踪 Manifest 识别技术栈，排除兄弟及嵌套 Worktree；检测到规范仓库内部嵌套工作目录时停止源码实现路由。
- 新增轻量 Worktree 库存器，快速模式只解析一次 `git worktree list --porcelain`；标准和深度模式只在创建、恢复、合并、发布或安全收敛时按需执行。
- 新增「工作目录安全收敛」原子 Skill，支持历史 Worktree 只读接管、证据分类、清理计划、安全 Token 和执行前重新验证；禁止批量强制删除及自动删除分支。
- 创建 Worktree 前强制检查项目初始化、真实活动预算和嵌套工作目录；租约增加活动、到期和复核时间，暂停到期只提醒复核、不自动删除。
- 任务状态增加 `MergedPendingCleanup`；合并完成但任务 Worktree 尚未关闭时不能进入 Merged，避免已完成任务长期留下源码副本。
- 对账器增加开发、创建、合并和发布阶段严重度：普通开发允许清点历史债务，创建与发布阻断未纳管工作目录，嵌套 Worktree 始终阻断。
- 实测 30 次本地冷进程路由 P95 为 97.32ms；现有前端 23 个、后端 33 个 Worktree 的快速库存约 210ms/237ms，均不读取源码内容。
