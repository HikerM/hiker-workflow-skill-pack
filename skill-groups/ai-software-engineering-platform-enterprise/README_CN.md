# 智能软件工程平台 5.10（超长会话与有界工程记忆版）

这是面向 ChatGPT Work / Codex 桌面端的大型软件工程插件套件。它不再把所有能力堆进一个超长 Skill，而是拆成 5 个可独立启用的中文插件：

1. **智能工程核心**：项目识别、真实版本检测、项目专属规范、任务状态、压缩保护和恢复。
2. **浏览器端与服务端工程**：非模板化设计系统、浏览器端组件实现，以及跨 Node/TypeScript、Python、.NET、JVM、Go、Rust、PHP、Ruby 的服务端识别、契约、迁移、实现和质量审核。
3. **客户端工程**：通过轻量路由按需支持Unity、Qt、.NET桌面、Electron/Tauri、Flutter、Android、Apple原生、React Native、Java桌面和嵌入式HMI；保留Unity Prefab/Scene/meta专项能力。
4. **工作区与多会话协作**：七角色控制平面、项目/任务状态、长链路收敛、Context Snapshot、多项目隔离、文件锁、Worktree、验收闭环和Git合并治理。
5. **质量、风险与发布**：独立设计就绪复审、完整本地变更集、设计变化影响、SQLite 增量图谱、回归测试计划和发布证据。

当前套件包含 5 个插件、42 个原子能力。只有用户可见的“智能工程轻量路由”可隐式触发，其余41个能力手动可见并按需懒加载；正常回执只显示实际应用的中文插件和中文 Skill 名称。路由先确认唯一 Git Worktree 并只读取当前源码的跟踪 Manifest；历史工作目录由快速库存、只读接管、证据分类、两阶段安全关闭和合并后收敛控制。0→1项目先建立稳定需求ID、冲突/未知账本和技术决策Checkpoint；用户提供的架构或功能拆分被视为待验证假设，先反证、补全遗漏和比较有真实权衡的替代方案；已有部分源码的项目先建立证据化能力基线并做需求差异对账。大型界面按当前模块治理隐藏表面、状态机、浮层、焦点、快捷键、请求乱序和重复提交，不扫描全仓交互配置。复杂长链路任务额外登记分层验收、唯一实现路径、真实实验预算和部署哈希；只有工程健康状态变化时才向用户显示去重中文告警。

个人安装器默认完成插件复制、个人Marketplace注册、五插件CLI安装启用，以及 `~/.codex/AGENTS.md` 全局自动应用/回执区块的安全合并。原规则会保留并备份，重复安装保持幂等；CLI不可用时输出手动命令。

## 关键约束

- **一次识别，多次复用**：领域插件读取 `.ai/context/`，不得重复全仓库技术栈分析。
- **唯一隐式入口**：只由 `ai-engineering-router` 参与自动选择；它不占额度，每阶段最多加载两个活跃原子 Skill，第三个及之后进入待执行队列，不静默丢失。
- **0→1先融合再编码**：稳定 Requirement ID、revision history、冲突/未知和技术决策Checkpoint防止自定义需求被固定模板吞掉。
- **架构不盲从**：保留用户目标，但主动检查边界、状态、数据、契约、安全、可靠性、性能、部署、测试和演进；只深入会改变决策的高风险项，最多给三个真正不同的方案。
- **存量源码先对账再修改**：用 `CAP-*` 记录现有能力与代码/测试证据，把 `REQ-*` 分类为新增、修改、替换或移除，影响范围确认前禁止重新脚手架。
- **广覆盖不等于全量加载**：C/S使用小型入口路由，单次只加载当前技术族和设计/实现/审核中的一个阶段。
- **持续执行但可随时中断**：用户说“暂停、调整、继续、回滚、查看状态”时，核心 Skill 与状态脚本更新运行状态，不要求每一步审批。
- **超长单会话与多轮压缩可恢复**：固定大小工作集只注入当前目标；关键需求、决定、任务和证据先写入正式状态，Skill 路由只保存阶段/名称/指纹。压缩后按项目身份、Task、Git、文档、Checkpoint恢复，不依赖聊天摘要猜测。
- **`.ai` 大也不能拖慢日常操作**：热目录只保留当前状态、有界任务索引和少量近期/里程碑 Checkpoint；旧 Checkpoint 压缩到冷归档并保留哈希与精确索引。日常启动、路由、任务创建和状态渲染不得扫描全部 Task 或归档。
- **一个 Git 仓库，多 Worktree**：并行写任务使用独立 Worktree；默认最多两个活动写任务、两个待收敛任务，先消化审核/测试/合并债务再扩大并行。
- **不把源码全文塞进知识图谱**：图谱使用 SQLite 存储导入、Unity GUID、.NET 项目引用和文件级关系，增量更新、限深查询和节点上限。
- **小改动也有边界**：每个受治理任务声明允许文件/模块、原有行为不变量和最低回归；超出范围、公共表面无消费者、图谱过期、依赖方向违规或文件异常增长会被架构守卫阻断。
- **治理不过度配置**：模块、依赖和运行拓扑默认自动发现；只有公共契约、受保护模块与静态分析无法证明的关系才渐进登记，禁止复制全仓事实形成第二套真相。
- **证据优先**：未执行的测试只能标记为“计划”，不能写成“通过”。
- **独立复审**：设计自检不能替代“设计就绪独立复审”；只有不存在 P0/P1 才允许进入编码。
- **视觉不能单调或模板化**：新增/重做 Web UI 必须有设计系统、语义色彩、间距尺度、组件复用、视觉焦点、疏密节奏和服务任务的签名元素。
- **交互治理按风险升级**：UI设计、实现或修改先加载当前平台主阶段Skill；只有出现隐藏表面、浮层/焦点/快捷键冲突、请求乱序、重复提交、导航离开或跨模块状态时，才按需加载“交互状态与冲突治理”。静态页面和普通局部交互不会额外加载。
- **交互检查保持有界**：只读取当前模块契约；无适用契约时返回 `NOT_APPLICABLE`，上限为1 MiB、500个交互、每项64个状态和256条转换，错误与警告各最多50条，不递归扫描源码或全部页面。
- **长链路必须收敛**：跨模块、多仓库、真实外部执行、部署回滚或同一目标反复修复时启用分层验收和实验门禁；同一验收点连续两次真实失败后必须换方案，不能继续叠加补丁。
- **同一职责唯一实现路径**：活动路径只能有一个；迁移兼容必须登记退出条件，合并前完成退役并提供删除或不可达证据，压制新旧代码长期混用和文件持续膨胀。
- **重要问题主动透明**：范围扩大、用户纠正、证据矛盾、方案失效、回滚、实现路径分叉或部署漂移时，输出一次中文工程健康告警，明确问题、影响、处置和下一门禁；状态不变不重复。
- **治理不能代替交付**：业务源码/可运行能力进展与控制账本/门禁进展分开显示；连续两个治理周期没有业务增量时停止增加投影和全量矩阵，相同指纹的未失效 PASS 直接复用。
- **延迟任务不重复启动**：`clientThreadId` 只登记为 `SETUP_PENDING`；确认 pending lease 到期且没有真实任务前，不创建同一 Task 的恢复会话或第二个 writer。
- **全局透明应用**：会话第一条助手输出先显示中文轻量路由名称；确定性路由后再显示实际活跃原子 Skill。相同阶段不重复，阶段切换或压缩恢复时重显。
- **发布级全套审计**：增强插件套件时检查五个插件全部 Skill 的登记、触发重叠、职责曲解、权限、手动提示、路由覆盖和上下文体积；普通项目请求不会执行这项全量审计。

## 推荐启用组合

- 浏览器端项目：智能工程核心 + 浏览器端与服务端工程 + 工作区与多会话协作 + 质量、风险与发布
- 客户端项目：智能工程核心 + 客户端工程 + 工作区与多会话协作 + 质量、风险与发布；后端通过独立服务通道协作
- 浏览器端 + 客户端混合项目：全部 5 个
