## 大型工程保护

- 每个开发 Task 在进入 Development 前必须具有允许范围、原有行为不变量和最低回归测试。
- 默认最多两个活动写任务、两个处于 Review/Testing 的待收敛任务和五个未关闭任务；达到预算后禁止继续制造写任务、开放任务或合并债务。
- 任务对账器提供快速、标准、深度三级检查，核对 Task、Branch、Worktree、文件锁和并行预算；创建或发布阶段遇到孤儿/嵌套 Worktree 会阻断，普通开发阶段只给出有界告警。
- 新增“工作目录安全收敛”：快速清单不扫描源码；旧 Worktree 先登记再治理；关闭必须经过计划与执行两阶段，并重新校验脏状态、合并目标、独有提交、HEAD 和安全令牌，禁止批量强制删除。
- 生命周期新增 `MergedPendingCleanup`，任务合并后必须先收敛对应 Worktree 才能进入 `Merged`，避免代码已合并但目录和任务状态长期堆积。
- 架构守卫检查范围漂移、公共表面指纹、消费者回归、依赖方向、受保护模块、文件体积与单次增长。
- 工程图谱除源码 import 外，还解析 Unity GUID 资源引用、.NET ProjectReference 和 Protobuf import；Unity资源与项目引用已改为按变更增量重建，仅 `.meta` 映射变化时做必要的语义全量重算。
- 架构证据绑定 Git HEAD 与工作区指纹；代码变化后旧证据失效，不能拿旧结果通过 Review、合并或发布门禁。
- 采用零配置可运行、约定优先、渐进增强；普通改动不要求维护与源码重复的庞大全量配置，高风险边界才要求显式登记。
