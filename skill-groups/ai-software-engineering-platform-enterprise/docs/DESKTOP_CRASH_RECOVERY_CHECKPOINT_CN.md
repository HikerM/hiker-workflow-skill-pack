# Codex 桌面稳定性修复 Checkpoint

## 已确认问题

- 超长桌面任务在恢复时重建过多历史项，会显著放大内存、持久化和重试压力。
- 任务意外中断可留下“工具调用存在、调用结果缺失”的历史；后续继续该任务时会重复失败。
- WebSocket/TLS 网络中断与自动重试会放大上述不一致。
- 旧安装版插件含高频生命周期 Hook，两个插件的 `defaultPrompt` 超过桌面支持的3项。
- 发布级测试工具曾把完整测试日志内嵌到回传中，长输出会增加任务历史体积。

## 已完成源码修复

- Windows运行时释放探针改用只读进程句柄查询存活状态，避免 `os.kill(pid, 0)` 干扰被探测进程。
- 删除智能工程核心和工作区协作插件的自动 Hook。
- 两个超限 `defaultPrompt` 均收敛为3项。
- 长会话纪元默认阈值收紧为20个实质轮次、40次工具调用、60000字符工具输出或1次压缩；达到任一阈值后禁止当前纪元继续实质执行。
- 测试日志改为证据文件，对话和 `test-results.json` 只保留有界摘要。
- Web UI 审核的自动模式不再在无变更时退化为全仓扫描；显式全量扫描上限5000个源文件和200条对话发现。
- 新增桌面稳定性发布门禁：禁止Hook、限制提示项、Skill体积、单文件体积和测试报告体积。

## 已完成本机紧急止血

- 已安装的智能工程核心与工作区协作插件已删除自动 Hook。
- 已安装的智能工程核心和浏览器端与服务端工程插件已收敛为3条 `defaultPrompt`。

## 自动推进偏离修复（2026-08-24）

- 无 `.ai` 项目改为无状态轻量推进，不再被误判为恢复故障。
- 只有与当前源码身份一致的 `.ai` 才能恢复 Task、路由、锁和既有 PASS。
- 缺少可信 provenance、仓库身份冲突或历史分叉的旧 `.ai` 自动隔离；普通设计、实现、审核和测试继续以最新用户请求与当前 Git 为准。
- 隔离状态禁止旧任务恢复、多会话/Worktree创建、合并和发布；`project-bootstrap` 不得补写 provenance 把旧状态自动变成可信。

## 不可误报的边界

插件可以减少触发条件，但不能修复已写入旧任务的缺失工具结果，也不能保证永不出现桌面端、网络或服务端故障。已损坏的超长任务必须停止继续执行。
