# 总控推进多维评估清单

本清单是智能软件工程平台的发布门禁，不是教程。静态文案、脚本返回 `ok` 或治理文件数量不能单独证明总控可用；每个维度必须有真实状态迁移、Git、测试、上下文、性能或资源证据。

## 1. 小型与局部任务

- 零配置可运行，不强制多Agent、Worktree、全量图谱和全量测试。
- 每阶段最多加载两个原子Skill；轻量路由不计入上限。
- `contract_change=false` 时不建立契约/数据库前置通道。
- 文档、合并和发布按风险进入，局部任务不展开完整生命周期。
- 必须完成真实业务源码提交；没有Commit、架构守卫和冻结候选时不得进入Review。

## 2. 大型、复杂与多仓库工程

- B/S、C/S、纯后端、混合和多仓库均可按真实变更契约动态拆分。
- 动态通道必须声明稳定ID、技术表面、仓库键和真实写范围，不以关键词或固定前后端模板替代模型判断。
- 规划态最多8个通道，运行态最多2个活动writer；第三个通道排队。
- 父子路径、公共契约、Migration、核心Service、权威状态、Unity受保护资产和共享测试环境冲突时强制串行。
- 不得通过修改Task ID、角色别名或通道别名绕开预算。

## 3. 总控推进与等待真实开发

- 分开记录业务价值进展和治理进展。
- 变更契约、行为不变量和最低回归满足后进入Development。
- 连续两个治理周期没有业务增量时停止新增投影，进入首个安全开发切片。
- Developer没有真实源码、Commit和候选证据时，总控必须等待，不得代填Review PASS。
- Review、Testing、Merge分别等待独立证据；源码或候选变化后旧PASS失效。
- 桌面任务查询失败只禁止盲建替代会话，不需要新隔离运行时的现有工作继续。

## 4. 长期总控与多轮压缩

- 跟踪有效轮次、工具调用、工具输出字符、压缩次数和阶段切换。
- 达到阈值后先Checkpoint，再建立唯一替代总控并归档旧运行时。
- Task变化不创建新总控；实现、修复、审核和复验复用稳定槽。
- 根上下文只保存总控摘要，每个活动Task使用独立上下文包。
- Task历史超限后进入带哈希链的冷归档；日常status/quick只读活动索引。
- 完整脱敏日志和diff写证据文件，对话只接收有界摘要、路径和指纹。

## 5. 总控中途调整目标

- 项目目标具有稳定ID、修订号、验收ID、不做事项、不变量、约束、优先级和指纹。
- 用户调整方向后，旧Task立即判为过期，不得沿用旧聊天摘要。
- 旧Task重绑定当前目标修订后才可恢复推进。
- 调整前先保存Checkpoint、当前修改和未完成事项。
- 只失效受影响结论，不粗暴删除需求、Task、决定和证据原件。

## 6. 质量、稳定性与交付

- Task声明允许范围、原行为不变量、公共消费者和最低回归。
- 新增职责前检查模块边界、依赖方向和文件增长，不等超行数才拆。
- 同一能力只有一个权威活动实现和一个权威状态写入者；迁移路径有退出条件和删除Gate。
- 网络、并发、第三方和容器链路分别验证超时、取消、幂等、重试、乱序、降级和恢复。
- 阻断正式运行路径中的Demo、Mock、Fixture、占位数据和用户可见内部诊断。

## 7. 性能与额度

- 路由只读浅层Manifest、有界 `.ai` 热状态和活动索引。
- 非Git目录不得重复启动无效Git子进程；同一轮不得重复项目识别和上下文预算计算。
- 20次冷进程路由P95必须低于500毫秒。
- 相同Gate、源码/契约指纹和范围已有PASS时复用证据。
- 单个Skill正文不得无限增长；发布审核检查结构、路由、职责、权限、可用性和性能。

## 8. 自动场景门禁

`tools/evaluate_master_progression.py` 每次发布运行四个独立临时工程场景：

1. `small_real_progress`：局部任务跳过无关契约通道，治理退出到Development，Review在真实Commit前被阻断；
2. `large_dynamic_parallelism`：两个独立writer并行，第三个排队，父子写范围冲突被阻断；
3. `long_master_and_output`：会话纪元达到阈值后Checkpoint轮换，大输出只返回有界摘要；
4. `goal_adjustment`：目标修订使旧Task过期，重绑定后恢复Planning。

任何场景失败、路由性能超限、120项单元回归失败、42-Skill一致性审核出现错误或警告、公开内容发现敏感信息时，版本均不得发布。
