# 05 质量、风险与发布

本插件负责设计就绪、真实变更集、回归范围、工程图谱影响和发布证据的独立只读审核。它不负责业务实现，也不会把设计自检、测试计划或建议状态写成已经通过。

5.11 要求审核绑定不可变候选，候选漂移立即使旧结论失效；大规模测试矩阵执行前先验证工具自身的运行时、路径、计数、变异和正反样本。跨会话或外部审核交接先扫描并脱敏密码、令牌、私钥和带凭据 URL。

包含：

- `design-readiness-review`：编码前独立重建“需求→工作流→页面→设计系统/Token→组件→数据→API/事件→权限→测试→证据”追踪链，审核内容是否足以实现、验收并形成有辨识度的 UI；缺少间距、色彩、组件复用、视觉焦点和节奏，或命中普通后台模板、Bootstrap 式默认视觉、重复卡片汤时按 P1 阻断；
- `full-change-risk-review`：覆盖完整变更集，并在需求、架构、数据、API/事件、UI、权限或测试设计变化时计算增量影响、判断是否重开设计复审；
- `knowledge-graph-maintenance`：增量维护文件级工程关系图谱；
- `regression-test-planner`：按真实变更和项目脚本生成最低必要回归范围；
- `release-readiness-review`：依据风险、构建、测试、迁移和回滚证据审核发布。

关键原则：

- `all-local` 同时覆盖暂存、未暂存和未跟踪文件；
- 自检 PASS 不替代独立复审，ID、数量和引用存在不替代语义充分性；
- 新增要求只重开受影响追踪链和共享消费者，不预设审核轮数；
- 当前文档相互一致不能证明范围完整，必须与独立批准基线比较；
- 未执行测试只能标记为计划，缺少证据时阻断或降级。
