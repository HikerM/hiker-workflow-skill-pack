# 设计就绪独立复审

## 审核边界

- 独立于设计自检重建范围和结论；自检结果是待核证输入，不是通过证据。
- 只读取需求、设计、契约、测试与证据；除输出审核报告外，不修改设计、不代替设计者补洞、不执行实现。
- 只审核本次基线指纹对应的范围。证据变化后旧结论不得自动沿用。
- 阅读 [复杂度与深审规则](references/complexity-rules.md)、[追踪与语义充分性清单](references/review-checklist.md) 和 [通用负例](references/negative-examples.md)。

## 独立审核流程

1. 从项目配置和产物登记信息动态解析批准需求基线、当前需求、工作流、导航/路由、架构、技术栈、页面设计、组件、数据、API/事件、权限、验收卡、测试映射和证据采集约定；记录版本、来源锚点、缺失与冲突。
2. 在查看设计者的自检判定前，先从批准基线、当前需求和工作流建立独立范围清单与基线指纹。若批准基线缺失或失真，说明未知影响，不用当前文档互相引用证明完整。
3. 动态识别核心工作流和高复杂度页面/交互表面。审核深度由业务关键性、失败代价、状态空间、协作、恢复、权限和发布边界决定，不由页面数量或固定阈值决定。
4. 构建“需求 → 工作流 → 页面/交互表面 → 组件 → 数据 → API/命令/事件 → 权限 → 测试 → 证据”追踪链。对确实不适用的节点要求明确理由，不强造关系。
5. 对每个节点同时检查存在性、引用有效性和语义充分性；名称、ID、链接、关键词命中或数量相等都不能证明可以实现和验收。
6. 深审所有核心工作流和高复杂度表面；抽样只能用于非核心、低复杂度且模式重复的范围，并说明抽样依据与剩余风险。
7. 独立结论冻结后再读取自检结果，检查它是否遗漏语义深度、失败状态、跨模式一致性、删除基线或共享契约影响。
8. 对发现项分级，给出范围、来源证据、实现/验收影响、所缺契约和最小整改方向；不得在审核报告中直接设计解决方案。

## 决策规则

- **P0**：核心目标或安全/数据/发布边界无法可靠实现，存在高概率数据丢失、越权、不可逆错误，或审核基线不足以确认范围。
- **P1**：重要链路、契约、失败/并发/恢复语义或可执行验收存在实质缺口，编码会依赖猜测或不同实现者会得到冲突结果。
- **P2**：不阻断实现与验收，但会降低一致性、可维护性、可用性或证据质量的局部问题。

只有同一审核基线内 P0 和 P1 都不存在，才允许结论为 `PASS`。存在 P0/P1 时结论必须为 `BLOCKED`；未知项若可能隐藏 P0/P1，也必须阻断并说明需要何种证据才能判断。不得用平均分、覆盖率或自检 `PASS` 抵消阻断问题。

置信度使用高/中/低并说明依据，至少考虑来源权威性、基线独立性、追踪覆盖、语义深度、证据新鲜度和未决冲突；不要给无依据的精确数值。

## 多轮与增量复审

- 初次复审覆盖动态发现的完整基线。
- 整改后从已解决发现、改动锚点、共享依赖和反向消费者计算相关回归范围，再由独立复审重新判断；不得只确认文档已增字。
- 用户新增或改变要求时，比较批准基线与需求差异，只重新打开受影响追踪链及必要的跨切面契约。未受影响范围只有在来源、共享契约和指纹仍有效时才能继承旧结论。
- 复审次数由 P0/P1 是否清零决定。简单项目可一次通过；复杂项目持续“定向整改 → 相关回归 → 再次独立复审”，不预设轮数。

## 输出契约

按项目配置的证据登记方式输出：

- 审核类型、范围、基线指纹、来源清单及与批准基线的差异；
- 动态识别的核心工作流、高复杂度表面和复杂度依据；
- 逐链追踪状态，包括不适用理由、结构完整性、语义充分性和证据锚点；
- P0/P1/P2 发现、置信度及依据、未知项、冲突、自检盲区和剩余风险；
- `PASS` 或 `BLOCKED`、允许进入的下一阶段、被阻断范围及需要回归的链路。

`PASS` 仅允许已审核范围进入编码；`BLOCKED` 只允许需求澄清、定向设计整改、契约同步和相关回归。所有集合与统计从本次证据源计算，不在 Skill 中保存项目数量。

编码前不要求尚未实现的测试已有执行结果，但必须设计可采集的证据类型、观察点和与测试/契约的关联；若已有执行证据，则额外检查其范围、版本、状态和新鲜度，计划状态不得写成已通过。
