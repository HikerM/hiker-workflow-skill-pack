## 识别高复杂度表面

从需求、工作流、数据/接口设计和验收中寻找能力信号，不依赖页面标签或固定分数：

| 能力信号 | 深审焦点 |
| --- | --- |
| 结构化编辑、富文本 | 类型化内容模型、约束、操作语义、选择/粘贴、撤销、引用、兼容 |
| 媒体或资源处理 | 上传生命周期、校验、处理状态、引用、替换/删除、失败恢复、权限 |
| 空间画布、关系或流程编排 | 真实节点/边模型、几何与层级、连接规则、操作历史、序列化、替代交互 |
| 实时通信或协作 | 连接、顺序、去重、重连、在线状态、并发控制、不可用降级 |
| 自动保存或离线恢复 | 脏状态、版本、节流、队列、重试、恢复点、过期、重新同步、冲突 |
| 审核、发布或快照 | 草稿、审核版本、不可变快照、可见性、生效、回滚、历史链接、审计 |
| 多角色或细粒度权限 | 角色/对象/动作/字段/状态规则、拒绝体验、服务端执行、信息隔离 |
| 大文件或大规模数据 | 限额、分块/流式、分页/虚拟化、进度、取消、超时、资源边界 |
| 高影响或不可逆操作 | 预览、确认、幂等、部分成功、补偿、回滚、审计证据 |

存在任一非平凡状态、一致性、恢复或发布风险时，按高复杂度审核。证据不足时标记复杂度未知并按潜在高复杂度处理，直到补证。

## 识别核心工作流

综合以下事实识别，不按固定数量选取：

- 直接实现主要用户结果或合同验收目标；
- 高频、跨角色、跨页面或跨系统；
- 涉及资金、敏感数据、权限、审批、发布或不可逆变化；
- 失败会造成数据丢失、错误公开、业务中断或难以恢复；
- 是其他流程的前置条件或共享依赖。

记录入选或排除依据。不得只审核“首页”或路由清单中的前几项。

## 深审要求

高复杂度表面必须有足以回答以下问题的证据：

1. **数据**：真实领域类型、字段约束、标识与用户显示分离、引用、版本、生命周期和兼容边界是什么？
2. **命令/事件**：输入输出、前置条件、权限、幂等、顺序、成功后状态、失败分类与补偿是什么？
3. **状态**：界面、领域、同步、权限、审核、发布状态如何区分，哪些转换被允许或拒绝？
4. **并发/恢复**：并发单位、版本条件、冲突检测与用户决策是什么；保存失败、断网、重连、重复提交和过期恢复如何处理？
5. **降级/容量**：实时、媒体或网络能力不可用时保留什么能力；大文件/数据如何限额、进度、取消和恢复？
6. **发布**：草稿与快照如何隔离，审核对象是什么，发布失败是否原子，历史引用与回滚语义是什么？
7. **验收**：是否有可执行的成功、失败、权限、并发、恢复、降级和发布场景，且断言到可观察状态或证据？

不适用项必须有来自真实能力边界的理由。只写“框架支持”“后端处理”或“按现有逻辑”不充分。

## 审核取证原则

- 以精确来源锚点和版本为证据，不以文档名称代替内容。
- 先看语义，再看引用和计数；引用到空壳契约仍是不充分。
- 对共享数据、权限、事件和发布模型检查所有消费者，避免单页面局部通过。
- 对重复的低复杂度模式可抽样，但任何核心流程、高复杂度表面或差异项必须全量深审。
- 设计图只能证明布局与状态呈现，不能单独证明数据、API、权限、并发或发布契约。
