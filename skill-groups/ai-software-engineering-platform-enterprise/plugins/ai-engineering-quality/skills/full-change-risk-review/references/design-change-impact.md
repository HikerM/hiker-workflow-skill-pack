## 识别语义设计变更

先从项目配置、产物登记和内容标记识别文档职责，再读取差异。路径只能作为线索。下列语义变化会使设计证据可能失效：

- 需求：角色、目标、规则、约束、范围、工作流、结果、验收；
- 架构：边界、依赖方向、状态归属、同步方式、外部系统或共享能力；
- UI：页面/表面、组件责任、入口出口、操作、状态、响应式或用户可见内容；
- 数据：实体、字段类型、约束、引用、标识、版本、生命周期、迁移、敏感级别；
- API/事件：输入输出、错误、鉴权、幂等、顺序、状态效果、兼容版本；
- 权限：主体、对象、动作、字段、状态、允许/拒绝规则与拒绝体验；
- 质量：验收卡、测试场景、映射、断言、运行条件、证据要求。

格式整理、拼写修正或不改变上述语义的重排可判为非语义变化，但需要差异证据，不能只按提交说明判断。

## 增量影响闭包

对每个变更锚点计算最小但完整的闭包：

| 起点 | 直接向下游检查 | 必须反向检查 |
| --- | --- | --- |
| 需求/验收 | 工作流、表面、权限、测试 | 共享规则和其他依赖该验收的流程 |
| 工作流 | 表面、状态、命令、失败/恢复、端到端测试 | 上游触发与下游结果消费者 |
| 页面/组件 | 数据、API/事件、权限、状态、交互测试 | 复用该组件或共享状态的其他表面 |
| 数据/Schema | API/事件、UI 投影、迁移、兼容、测试 | 所有读写方、引用方和发布快照 |
| API/命令/事件 | 调用方、消费者、错误体验、契约测试 | 生产者、重试/幂等与版本依赖 |
| 权限 | UI 可见性、服务端执行、拒绝体验、安全测试 | 所有使用该角色/对象/动作的流程 |
| 发布/快照 | 审核、预览、阅读、回滚、历史引用、验收 | 草稿编辑、共享数据与公开消费者 |
| 测试/证据 | 覆盖声明、门禁和发布结论 | 对应需求与契约是否也改变 |

横切面包括用户可见信息隔离、多模式一致性、并发、离线恢复、降级、大文件和发布。只有在证据证明不受影响时才从闭包中排除。

## 用户新增要求

1. 将新增内容拆成角色/目标/规则/工作流/约束/验收差异，保留对话或正式记录锚点。
2. 与批准基线比较，标记新增、修改、删除、冲突和待批准项。
3. 从差异节点计算页面、组件、数据、API/事件、权限、测试和证据影响。
4. 区分“需要设计更新”“需要独立复审”“可能需要代码变更”，不把尚未设计的要求直接当实现任务。
5. 未受影响链只有在共享契约和基线指纹未变化时才保持关闭。

## 表面整改识别

以下迹象说明整改可能只修文档表面：

- 页面说明增加了状态或动作，但数据与 API/事件契约没有相应字段、错误或状态效果；
- API 描述换了名称，Schema、鉴权、幂等、版本和契约测试未变化；
- 数据文档补了说明，但仍使用不透明字段承载已知结构；
- 权限只在界面隐藏，服务端规则和拒绝测试未同步；
- 并发、恢复、降级或发布只增加一句原则，没有状态转换、命令条件和验收；
- 测试映射增加 ID 或数量，核心场景仍没有前置、动作、断言和证据；
- 先前发现被标记已解决，但改动指纹不覆盖该发现指出的契约层。

风险审核只指出不同步和复审范围，不负责生成新的 UI、数据或接口设计。

## 独立基线与误删防护

- 将当前集合与批准需求基线、签署清单或不可由当前文档共同改写的范围记录比较。
- 同一变更中需求、页面、测试和追踪表一起删除同一项，仍应报告范围删除差异。
- 删除必须有显式批准、影响分析以及对依赖、数据、兼容和证据的处置。
- 无独立基线时，列为证据缺口并降低置信度；不得以当前文档内部一致证明完整。

## 复审触发证据

复审触发记录至少包含：

- 变更来源锚点及前后版本/指纹；
- 变化的语义，不只是文件列表；
- 受影响追踪链、共享依赖和排除范围理由；
- 旧设计就绪结论绑定的范围/指纹及为何仍有效或已失效；
- 需要重新审核的核心工作流、高复杂度表面、契约与相关回归；
- 复审尚未执行、已阻断或已取得同版本独立结论的真实状态。
