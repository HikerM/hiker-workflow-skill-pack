# 交互状态与冲突治理

## 边界

- 适用于 Web、非 Unity C/S、Unity、移动端和混合项目；先使用项目已经识别的框架、版本、组件库和输入模型，不写死实现技术。
- 治理交互语义和冲突，不代替页面设计、组件实现、业务服务或平台专项测试。
- 只处理当前模块或本次变更涉及的交互。不得预读全部页面、源码、历史契约或完整聊天记录。
- 保持约定优先：没有交互契约且本次不涉及高风险交互时返回 `NOT_APPLICABLE`，不得为了治理而生成全项目配置。

## 最小交互单元

关键交互必须形成：

`触发表面 → 状态转换 → 命令/事件 → 并发策略 → 退出/恢复 → 可执行证据`

至少明确：

- 稳定 `INT-*` ID、所属模块、所有者和作用域；
- 默认、打开、加载、成功、空、错误、禁用、权限、关闭或取消等适用状态；
- 触发事件、来源状态、目标状态、业务命令及失败路径；
- 异步策略：`latest-wins`、`single-flight`、`queue` 或 `idempotent`；
- 页面卸载、父表面关闭、权限变化、请求被替代和网络中断时的取消/丢弃规则；
- 浮层、焦点、键盘/手柄/触摸、导航离开及未保存数据规则；
- 默认状态以外的截图、日志或自动测试证据。

## 执行流程

1. 读取当前任务契约和当前模块的交互契约；没有明确要求时不得加载其他模块。
2. 发现交互表面，包括下拉框、菜单、弹窗、抽屉、Popover、Tooltip、日期选择、树选择、表格行操作、上传、编辑器、通知、响应式导航和拖拽。
3. 区分组件本地、模块和全局状态。能放本地的不提升为模块状态，能放模块的不提升为全局状态。
4. 为本次新增或修改的关键交互补齐状态图、并发、取消、权限、焦点、导航和证据要求；不复制源码中的静态结构。
5. 运行：

   ```powershell
   py -3 <plugin-root>\scripts\interaction_guard.py --root . --mode review
   ```

   也可用 `--contract <当前模块契约.json>` 限定单文件。只接受有界 JSON 契约，禁止递归扫描源码。
6. 对阻断项修正设计或实现，再执行当前模块的真实交互测试。不得把“契约校验通过”冒充“运行时交互已通过”。

当前模块的最小契约形状：

```json
{
  "schema_version": "1.0.0",
  "module": "当前模块稳定标识",
  "interactions": [{
    "id": "INT-MODULE-ACTION",
    "owner": "当前模块",
    "scope": "current-window",
    "surface": "combobox",
    "initial_state": "closed",
    "states": ["closed", "open", "loading", "loaded", "empty", "error"],
    "transitions": [
      {"event": "open", "from": "closed", "to": "open"},
      {"event": "search", "from": "open", "to": "loading", "async": true, "policy": "latest-wins", "cancel_on": ["superseded", "close", "unmount"]}
    ],
    "overlay": {"kind": "combobox", "group": "current-window", "priority_token": "layer.dropdown"},
    "required_evidence": ["open", "closed", "loading", "empty", "error"],
    "evidence": []
  }]
}
```

示例中的模块、状态和证据必须替换为当前项目真实语义；不得复制示例业务名或虚构已执行证据。

## 冲突规则

- 浮层使用语义层级令牌和父子关系；禁止以不断增大的裸数字层级解决遮挡。
- 同一作用域和条件下不得注册重复快捷键；子作用域可覆盖父作用域，但必须声明优先级和焦点恢复。
- 异步搜索采用最后请求生效或显式队列；旧请求、已卸载页面和已关闭表面的返回值不得写回当前状态。
- 写操作采用单次执行或幂等策略；超时后先确认服务端结果，危险写入不得无条件自动重试。
- 路由跳转必须处理未保存状态；关闭父表面必须回收子浮层、监听器、请求和焦点。
- 跨模块只能通过公开命令、事件或服务契约协作；禁止组件直接修改另一个模块的内部状态。
- 全局交互内核仅承载浮层、焦点/快捷键、导航守卫、请求协调、通知和身份权限，不接收具体业务逻辑。

## 性能与规模预算

- 默认只读取 `.ai/ui/interaction-contracts.json`；模块任务优先显式传入单文件。
- 契约上限 1 MiB、500 个交互、每个交互 64 个状态和 256 条转换；超过时要求按模块拆分，不扩大全仓扫描。
- 检查器使用集合索引和有界图遍历，目标复杂度为 `O(交互 + 状态 + 转换)`；输出最多 50 条错误和 50 条警告。
- 不把所有交互注入当前会话，不建立运行时万能 Store，不维护与源码重复的组件树和全量事件表。
- 路由仍最多加载两个原子 Skill；本 Skill 不允许隐式调用，只由轻量路由命中或用户手动选择。

## 验收

- 当前变更涉及的关键交互都有稳定 ID、所有权、作用域、状态和退出路径。
- 隐藏表面具有打开、关闭、空、加载、错误、权限和输入方式中的适用证据。
- 不存在重复 ID、不可达状态、非法转换、同作用域快捷键冲突或裸数字浮层层级。
- 异步交互有乱序、取消、卸载和重复操作策略；写操作有幂等或单次执行约束。
- 已执行的测试与证据明确列出；未执行项标记为未验证。

## 禁止

- 不为简单静态页面生成交互治理文件。
- 不把所有页面状态提升到全局 Store，不创建万能事件总线或万能交互管理器。
- 不因缺少运行证据就声称交互已验证，不用默认截图代表隐藏状态完成。
- 不直接修改 `main`，不自动 push、merge、发布或部署。
