# 跨平台客户端约束

## Electron / Tauri

- 识别 Electron、Node、Chromium 或 Tauri、Rust、Web前端真实版本；保持主进程/渲染进程/命令边界。
- IPC/命令采用最小白名单、校验输入和版本化契约；不得为复用方便暴露任意文件、Shell或网络能力。
- 窗口、托盘、更新、深链和退出流程必须覆盖多实例、崩溃恢复与平台差异。

## Flutter

- 沿用真实状态管理、路由、依赖注入和平台通道方案，不平行引入第二套全局状态。
- Widget 保持可组合；业务状态、平台适配和渲染职责分离，验证桌面与移动生命周期、窗口尺寸和输入差异。

## React Native

- 沿用导航、状态、原生模块和构建体系；识别 Hermes、新架构及平台版本证据。
- 公共原生模块、事件和 JS/Native 数据结构变化必须登记双端消费者并做平台回归。

共同要求：共享业务语义，不强求所有平台组件结构完全一致；Design Token 可共享，生命周期、输入、窗口和平台能力适配保持局部，避免跨平台配置耦合。
