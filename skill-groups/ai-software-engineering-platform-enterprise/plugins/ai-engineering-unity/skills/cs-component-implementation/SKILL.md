# 通用C/S组件实现

1. 读取路由收据、已批准设计、Design Token、组件复用清单、API契约、锁定决策和影响文件；Unity改用 `unity-component-implementation`。
2. 沿用现有语言、框架、状态管理、导航、依赖注入、线程和构建/打包方式；不因插件支持其他框架而引入迁移。
3. 按“窗口/页面 → 业务组件 → 组合组件 → 基础组件 → 当前项目UI层”实现，颜色、间距、排版和状态映射到语义 Token。
4. 网络和数据访问通过既有客户端服务层；不在视图散落请求、数据库访问或设备协议。API变更先更新 `contract-data`，客户端与后端分别实现和验证兼容性。
5. 保持目标技术族的UI线程、生命周期、资源释放、取消、离线恢复、权限和平台差异约束。
6. 涉及隐藏表面、跨窗口、快捷键、异步乱序或重复写入时，只读取当前模块交互契约并执行 `interaction-conflict-governance`；不得把各窗口状态集中到万能全局容器。

禁止复制整页、滥建同形卡片、硬编码视觉值、绕过现有组件、把所有状态塞入全局容器、在UI线程执行阻塞I/O，或把“能编译”当作完成。

正式包不得默认启用 Demo/Mock/Fixture，不得展示占位数据、样例身份、本机路径、堆栈或设备内部诊断。旧窗口、旧服务或旧协议适配器仅可作为有退出条件的迁移路径，并且只能有一个权威数据写入者。

完成证据包括：构建、静态检查、单元/组件测试、关键流程日志、目标设备或窗口尺寸截图、键盘/触控等适用输入验证、离线/失败状态、API兼容结果、资源与性能检查、修改文件和未验证范围。
