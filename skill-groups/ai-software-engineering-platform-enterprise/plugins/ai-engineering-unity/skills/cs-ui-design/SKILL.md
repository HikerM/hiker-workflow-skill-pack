# 通用C/S界面设计

## 输入门禁

读取项目状态、当前任务、`tech-stack.json` 和 `cs-client-router` 收据。只读取命中技术族的路由小节；Unity改用 `unity-ui-design`。确认目标设备、窗口/屏幕模型、输入方式、联网模式、安装更新方式和后端/API版本。

## 设计契约

从真实角色、工作流和设备约束发现窗口、页面、面板、对话框、托盘/通知、后台任务及跨窗口状态。每个表面至少定义：

- 目标、入口、主路径、异常路径、完成结果和可验收证据；
- 平台原生习惯与品牌视觉方向、信息层级、焦点、密度和疏密节奏；
- 语义色彩、间距、排版、形状、层级、动效和明暗模式 Token；
- 现有复用组件、组合组件、新增理由、输入输出、状态和事件；
- 鼠标、键盘、触控、手写笔、手柄或设备按键中的实际适用输入；
- 窗口缩放、多屏/DPI、横竖屏、安全区、焦点、导航、生命周期和恢复；
- 加载、空、校验失败、网络中断、离线、重试、权限、设备不可用、升级不兼容和超长内容状态；
- API/事件的版本、请求响应、错误、取消、超时、重试、幂等和兼容边界。

## 视觉硬约束

不得套用普通后台、Bootstrap式默认视觉、统一白卡网格或组件库Demo。不得以“原生”或“简洁”为理由交付无视觉焦点、无层级、无状态表现的单调界面。视觉增强必须服务信息或交互，并满足对比度、减弱动画、性能和平台一致性。

## 输出与交接

输出技术族、设计系统、表面清单、组件契约、客户端状态机、API依赖、平台差异、验收矩阵和未知项。编码前交给独立 `design-readiness-review`；存在P0/P1不得进入实现。
