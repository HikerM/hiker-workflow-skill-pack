# B/S组件与页面实现

## 实现前

1. 读取 `.ai/context/tech-stack.json`；
2. 运行 [component_registry.py](../../scripts/component_registry.py) 更新组件清单；
3. 读取已通过独立复审的页面规格、API契约、视觉方向、Design Token、间距/色彩规范、组件复用清单和锁定决策；
4. 若设计缺少上述内容、复审仍有 P0/P1，或页面结构只是普通后台模板，停止实现并把缺口退回 `web-ui-design` 与 `design-readiness-review`；
5. 输出影响文件、Token 映射、复用/扩展/组合组件、新增组件理由和验证命令。

## 分层

```text
页面
→ 业务组件
→ 组合组件
→ 基础组件
→ 当前项目组件库
```

禁止：

- 页面直接散落 `fetch/axios`（除非项目架构明确允许）；
- 公共组件依赖具体业务模块；
- 复制整页形成新功能；
- 未评估新增生产依赖；
- 硬编码颜色、字号、间距、圆角；
- 把页面临时状态全部塞入全局 Store。
- 默认生成“侧栏 + 顶栏 + 四个指标卡 + 卡片网格”；
- 使用 Bootstrap 式默认配色、栅格、按钮、圆角白卡和统一阴影冒充项目设计；
- 为每个区块创建同形 `Card`，或复制组件库 Demo 后只替换文案；
- 绕过项目 Token 新增同义颜色、间距和组件变体；
- 为避免复用而复制组件，或为追求复用把语义不同的组件强行合并。

实现时所有颜色、间距、排版、圆角、边界、层级和交互状态必须映射到项目语义 Token。卡片仅实现设计契约中已有语义理由的内容单元；其余区域按排版、分区、列表、表格或主从工作区实现。

实现视觉丰富度时保留设计中的主焦点、疏密节奏、层次变化、签名元素和关键微交互。不得擅自把这些差异抹平成同一容器，也不得为了“更炫”新增无任务价值的渐变、发光、玻璃、阴影或动效。

## 连续执行

普通实现步骤连续完成并自动保存检查点。用户中途调整时只重做受影响部分，不丢弃已完成的服务、类型或测试。

## 完成证据

构建、类型检查、测试、目标分辨率与关键状态截图、Token 使用检查、组件复用清单、卡片语义核对、主焦点/节奏/签名元素还原证据、动效减弱检查、控制台错误、修改文件和未验证范围。
