## 判定原则

复杂度不是页面数量、控件数量或固定分数。结合业务关键性、状态空间、数据生命周期、协作风险、失败代价和恢复难度作语义判断：

- 仅展示或简单请求/响应、状态有限且失败可直接重试的表面，可采用标准设计深度。
- 任一能力要求非平凡的状态转换、长生命周期数据、协作一致性、不可逆结果或跨模式语义，即应采用深度设计。
- 多个复杂度信号叠加、位于核心工作流、影响发布内容或权限边界时，必须按高复杂度处理。
- 证据不足时标记“复杂度未知”，补证前不得把它降为普通页面。

不要用固定阈值替代判断。判定记录必须引用需求、工作流或技术约束中的证据。

## 复杂度信号

| 信号 | 必须回答的设计问题 |
| --- | --- |
| 结构化编辑或富文本 | 文档由哪些真实节点/块构成；字段、嵌套、约束、选择区、粘贴、撤销、引用和版本如何工作 |
| 媒体与资源 | 上传会话、校验、扫描/转码、进度、取消、重试、引用、替换、删除、权限和失效如何呈现 |
| 空间画布或关系编排 | 真实节点与边、几何/层级、选择、变换、连线约束、撤销、序列化和无障碍替代如何定义 |
| 实时通信 | 连接生命周期、身份、顺序、重连、重复/丢失消息、在线状态和不可用降级如何处理 |
| 自动保存 | 脏状态、触发条件、节流、请求版本、失败提示、重试、离开页面和恢复点如何定义 |
| 并发协作 | 并发单位、版本标记、冲突检测、合并/覆盖策略、锁或乐观控制、用户决策和审计如何定义 |
| 离线恢复 | 可离线范围、缓存边界、待提交操作、过期判断、重新同步、冲突和数据清理如何定义 |
| 审核与发布 | 草稿、审核版本、不可变快照、发布可见性、调度、回滚、历史链接和当前编辑之间如何隔离 |
| 多角色权限 | 角色、对象、动作、字段和状态组合的允许/拒绝规则，以及前后端双重执行与拒绝体验 |
| 大文件或大数据 | 限额、分块/流式、分页/虚拟化、进度、取消、超时、断点恢复和资源消耗边界 |
| 高影响操作 | 二次确认、预览、审计、幂等、补偿、回滚和部分成功语义 |

技术栈只约束实现选择，不能代替上述语义设计。若项目已有协议或组件，核对它是否覆盖当前需求，而不是因“已有”直接判定充分。

## 标准与深度设计边界

标准设计仍需提供可实现的数据和交互契约。仅当表面确实不读写业务数据、不发出命令且不参与状态转换时，才可对相应项标记不适用，并给出理由。

深度设计必须把复合能力拆为真实领域对象、操作和状态。名称应能让实现者与测试者理解它管理的业务对象及责任；只描述视觉容器、控件类别或序列化介质的名称不构成设计。

## 高复杂度设计检查面

### 领域模型

- 列出真实实体、值对象、节点/资源类型、字段类型、必填性、默认值、约束和不变量。
- 区分稳定业务标识、内部存储标识、用户可见标题与外部引用；定义版本与兼容边界。
- 对开放扩展点给出判别字段和每个变体的类型 Schema；不得以不透明 JSON 代替当前已知结构。

### 命令与事件

- 使用业务动作命名命令，说明输入、输出、前置条件、权限、幂等键、版本条件、成功后状态和失败类型。
- 定义事件生产者、消费者、顺序、去重、重放、确认与最终一致性边界；不适用时说明同步调用为何足够。
- 定义撤销/重做、取消、补偿或不可逆边界，不把界面按钮直接当领域命令。

### 引用与生命周期

- 说明对象之间是强引用、软引用、快照引用还是外部链接。
- 定义删除、替换、复制、导入、发布和回滚对引用的影响，以及断链的用户体验。
- 区分草稿引用与已发布快照引用，防止后续编辑悄然改变历史发布结果。

### 状态与恢复

- 分开描述界面状态、领域状态、同步状态、权限状态和发布状态，给出允许转换及守卫条件。
- 明确加载、部分加载、保存中、已保存、待同步、冲突、失败、只读、离线和恢复后的行为。
- 定义持久化恢复点、过期判断、重试上限、取消、离开保护与跨设备恢复边界。

### 并发与降级

- 选择并说明并发控制策略及其粒度；定义版本不匹配、同时编辑、重复提交和乱序到达的处理。
- 实时、媒体处理或网络能力不可用时，说明可继续的功能、只读边界、队列策略和用户可见状态。
- 不得把“稍后重试”作为唯一失败设计；说明数据是否保留、操作是否重复、用户下一步是什么。

### 发布与验收

- 定义发布输入、不可变快照内容、审核结论、可见范围、生效时机、失败原子性、回滚与审计证据。
- 验收场景必须能按前置数据、操作步骤、可观察状态和持久化/事件证据执行。
- 至少覆盖被识别出的关键成功、失败、权限、并发、恢复、降级和发布边界；覆盖集合按实际能力生成。
