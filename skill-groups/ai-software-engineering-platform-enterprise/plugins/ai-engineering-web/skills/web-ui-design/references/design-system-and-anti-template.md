# 设计系统与反模板约束

## 先定义项目自己的视觉语言

在绘制页面或写组件树之前，根据品牌、用户、任务频率、内容类型和使用环境记录：

- 3–5 个可验证的视觉性格词，以及每个词在排版、色彩、密度、形状或动效中的具体表现；
- 信息层级和阅读路径：什么必须先看、什么随操作出现、什么只在异常时出现；
- 页面构图语法：主工作区、辅助区、批量操作、上下文详情、跨页面导航分别如何组织；
- 明确不采用的模板惯性，例如默认仪表盘骨架、等宽卡片阵列或组件库示例页。

“现代、简洁、高级”不构成可实现的视觉方向，必须转换成可观察规则。

## 视觉丰富度契约

视觉效果提升来自清晰层级和受控变化，而不是装饰数量。每个关键页面至少说明：

- **单一主焦点**：本页最重要的对象或动作如何通过尺度、位置、色彩或留白优先呈现；
- **疏密节奏**：高频操作区、数据密集区和解释性内容如何使用不同但一致的间距节奏；
- **层次变化**：通过排版、边界、背景带、分栏、吸附区、主从工作区或渐进披露建立层次，不把阴影和卡片作为唯一手段；
- **内容化视觉**：只有在帮助识别、比较、定位或理解时使用图表、状态编码、图标、缩略图、插画或品牌图形；
- **状态表现**：加载、成功、警告、错误、选中、拖放、保存和发布状态具有一致且可感知的反馈；
- **微交互**：只为因果反馈、空间连续性或状态转换使用动效，说明持续时间、减弱动画策略和性能边界。

至少为核心页面提供一个能体现品牌与任务特征的“签名元素”，例如独特的信息总览方式、内容导航、数据比较、时间轴、工作区布局或状态语言。签名元素必须服务任务，不能只是无意义装饰。

避免两种极端：一是所有区域同样大小、同样颜色、同样容器导致单调；二是每个区域使用不同渐变、圆角、阴影和动效导致噪声。变化必须来自信息语义，并受同一 Token 与组件规则控制。

## 最小 Design Token 契约

不得只给一组十六进制颜色或零散像素值。至少定义：

1. **色彩**：背景、表面、正文、次要文字、边界、品牌动作、成功、警告、错误、信息、焦点和禁用等语义角色；记录前景/背景配对、对比度、交互状态和明暗模式映射。
2. **间距**：基准单位和有命名的尺度，说明控件内部、同组元素、分区、页面边缘、栅格/工作区间隙分别使用哪些档位；例外必须有内容或设备依据。
3. **排版**：标题、正文、标签、数据和辅助文字的字号、行高、字重与截断/换行规则。
4. **形状与层次**：圆角、边框、阴影和遮罩的层级及使用边界。不能给所有容器同一圆角和阴影。
5. **交互**：hover、active、selected、focus-visible、loading、disabled、error 的统一反馈。

若项目已有 Token，先输出复用映射和缺口，不创建同义 Token。若现有组件库只提供技术默认值，通过主题适配层映射到项目语义 Token。

## 组件复用契约

建立组件清单，并为每项标记 `复用`、`扩展`、`组合` 或 `新增`：

| 项目 | 必填内容 |
| --- | --- |
| 语义职责 | 组件解决的业务或交互问题 |
| 来源 | 现有组件路径、组件库能力或新增理由 |
| 契约 | 输入、输出、事件、插槽/组合点和数据边界 |
| 变体 | 由语义差异驱动的有限变体，禁止页面专属布尔参数堆积 |
| 状态 | 默认、交互、加载、空、失败、无权限、禁用和长内容 |
| 适配 | 响应式、键盘、焦点、辅助技术和主题映射 |

相同交互模式出现两次以上时先评估共享；语义不同但外观相近时不要强行合并。复用的目标是稳定契约，不是追求最少组件数量。

## 卡片使用判定

只有同时满足以下至少一项并记录理由时才使用卡片：

- 内容是可独立理解、选择、拖动、展开或跳转的整体；
- 内容需要与相邻区域形成清晰的交互或权限边界；
- 响应式重排要求该组作为完整单元移动。

单纯需要留白、分组或背景色不是卡片理由。指标、筛选器、表格、详情、图表和操作区不应自动各占一张同形卡片。连续内容优先使用排版层级、分区标题、列表、表格、分隔线、背景带或主从工作区。

再执行一次“移除表面测试”：临时去掉背景、圆角、边框和阴影。若信息层级、整体操作、权限边界和响应式移动关系没有改变，这个容器不是卡片，只是装饰性包裹，必须改用非卡片结构。组件名称不是证据；`Panel`、`Surface`、`Paper`、`Box` 或任意 `div` 也要按实际视觉和语义判断。

核心页面的构图契约保持一份紧凑记录，不为每种布局创建新文档：主任务、构图模式、第一焦点、阅读路径、疏密区域、签名元素、卡片理由和非卡片替代。独立复审只核对这份记录与实际页面，不重复生成全量设计矩阵。

## 编码前验收

- 页面结构可追溯到任务和内容层级，而非通用后台模板；
- 不依赖 Bootstrap 式默认配色、栅格感、按钮和白卡阴影形成视觉完成度；
- 色彩与间距全部能映射到语义 Token，且状态和对比度可验证；
- 组件树标出复用来源、新增理由、变体和状态；
- 每处卡片都有语义理由，不存在同形卡片包裹所有内容的“卡片汤”；
- 核心页面有明确焦点、疏密节奏、层次变化、状态反馈和至少一个服务任务的签名元素，不是单调的等权布局；
- 至少给出关键页面和关键状态在目标分辨率下的构图证据。

任一项缺失时设计结论不得标为可编码。
