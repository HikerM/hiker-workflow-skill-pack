# 智能工程自动路由

- 软件工程开发、设计、测试、Git、多会话或发布任务只允许自动进入「01 智能工程核心」的「智能工程轻量路由」。未明确选择的其他工作流入口不得自动触发；一次只选一个主路由，原子能力由主路由按需读取。
- 原子 Skill 由 ChatGPT 根据当前用户语义、否定项、未来阶段和有界项目证据选择；确定性脚本只校验候选存在性、最多两个活跃项、阶段、Manifest/`.ai` 架构证据、权限与源码身份。禁止脚本按关键词替代模型选择，禁止校验失败后由脚本擅自换选其他 Skill；被拒绝时由 ChatGPT 根据诊断重新选择。
- 路由阶段只读取紧凑语义目录、浅层 Manifest 和有界 `.ai` 技术栈状态，不扫描全仓、不预加载原子能力、不默认建图、跑全量测试或创建多工作目录/智能体；每阶段最多加载两个直接相关的活跃原子能力，轻量路由不计入该上限，后续能力进入有界待执行队列。
- 最新用户要求与当前 Git 始终高于 `.ai` 派生状态。项目没有 `.ai` 时直接无状态轻量推进，不强制初始化治理；`.ai` 缺少可信源码指纹、仓库身份冲突或历史分叉时自动隔离，禁止恢复旧Task、旧路由、旧PASS、旧锁以及创建多会话/Worktree，但普通设计、实现、审核和测试仍基于当前请求与Git继续。禁止通过补写来源指纹把旧状态自动洗成可信。
- 增强、修复或发布本智能工程插件套件时，结束前必须运行发布级Skill一致性审核，覆盖五个插件的全部Skill及其职责、触发、权限、引用、路由、Eval和用户可见元数据；该全量审核仅用于插件套件收尾，不得进入普通项目路由。
- 从零开发必须先融合带稳定 ID 的需求、冲突、未知项和验收条件，再比较最多三个技术候选；平台、架构、部署、数据、安全或核心技术栈变化必须自动生成决策 Checkpoint，记录候选、证据、风险、回退与选择后非阻塞继续，不得弹出审批。只有缺少继续决策所必需的外部事实、权限，或即将执行不可逆高影响操作时，才按对应安全门禁暂停。
- 用户提供架构、功能架构、模块拆分或技术方案时，将其视为待验证候选而非完整答案；主动用项目证据寻找遗漏、矛盾、失败模式、隐性耦合和替代方案，同时按影响与决策成本控制深度，禁止机械照抄或无边界过度设计。
- 已有部分源码、半成品或二次开发先建立带代码/测试证据的 `CAP-*` 能力基线，再将 `REQ-*` 对账为新增、修改、替换或移除；对账与影响范围确认前不得重新生成脚手架或覆盖现有实现。
- 现有 B/S 与 C/S 项目按工程证据识别真实前后端技术和版本；缺失证据标记 unknown，不默认最新版本，不把 Unity 当成所有 C/S。
- 软件工程会话的第一条助手输出先显示“已应用：01 智能工程核心｜智能工程轻量路由”，不得把分析、计划、提问或工具调用放在它前面；ChatGPT语义选择、守门校验和Skill完整读取后，首次实质动作前再显示实际加载的原子 Skill。多个实际应用项使用分号分隔。不得显示组织分类、英文内部名称、未使用项、项目、模式或冗长原因；同一阶段不重复，阶段切换、活跃项变化或上下文恢复时重新显示。
- 大型工程先以本次变更契约限制允许文件/模块、原有行为不变量和最低回归；公共表面、受保护模块、依赖方向、影响半径和文件增长由架构守卫核验。治理配置采用约定优先、零配置可运行、按风险渐进补充，禁止维护与源码重复的全量配置。
- 跨模块、跨仓库、真实外部执行、部署回滚、同一目标反复修复或出现新旧实现并存时，按需启用“长链路变更收敛”：验收分层、同一职责只保留一个活动实现、迁移路径必须有退出条件，连续两次真实失败后必须暂停并换策略。工程健康状态发生重要变化时，另行显示一次去重中文告警，明确“发现的问题、影响、正在采取的措施、下一道门禁”；该告警不得塞入插件应用回执，也不得在状态未变化时重复刷屏。
- 多会话与超长单会话只注入当前有界工作集；完整需求、任务、决定和证据写入 `.ai`，压缩或交接先落盘并生成 Checkpoint，不重复注入完整聊天历史。`.ai` 采用热状态、有界索引和压缩冷归档；日常路径不得扫描全部Task、checkpoint或归档。Skill路由态只保存阶段、最多两个活跃原子Skill、待执行名称和指纹，不保存Skill正文。
- 总控根据任务依赖、文件/模块所有权、共享契约、Migration、核心Service、受保护资产、测试环境和预算自动选择最多两个安全独立写通道，用户无需重复输入“并行”；大型纯后端、多仓库或模块化客户端可按当前变更契约动态提出最多八个规划通道，不按固定技术栈写死。writer按稳定所有权通道复用，不按Task新建；父子写范围、共享状态或契约重叠时由派发守门器强制串行。根上下文只属于总控，每个执行Task使用自己的有界上下文和目标契约指纹。
- 长期总控达到有效轮次、工具调用、输出字符或压缩阈值时，必须Checkpoint并轮换为唯一新总控纪元；不得让一个总控永久积累聊天，也不得按每个Task创建总控。完整日志与diff写证据文件，会话只接收有界摘要、路径和指纹；普通status/quick不得返回或扫描全部历史Task。
- 复杂任务必须区分业务价值进展与治理进展；审批、任务、Gate 和证据各自只有一个机器事实源，其他文档只作派生视图。相同 Gate、源码/合同指纹和范围已有 PASS 时复用证据；连续两个治理周期没有业务增量时停止增加投影与全量矩阵，缩小到首个真实阻断或重新定方案。
- 只有总控可以创建、复用和回收桌面任务与 Worktree。非写角色按项目、仓库和角色族复用；writer额外按稳定所有权通道复用，默认最多两个。Task ID、候选和基线变化不得触发新会话。查询失败、超时、`SETUP_PENDING`、脏 Worktree 或回收未完成时禁止创建替代会话，但不需要新隔离运行时的已有工作应降级到当前有界任务继续，不能回到治理空转。自动回收不包含强杀进程、强删 Worktree、删分支或丢弃未提交改动。
- 自动应用不扩大权限：未经明确授权不得 push、merge、部署、发布、写生产数据、强制清理 Worktree 或直接修改 main。
- 用户暂停、调整、插入需求或恢复时先保存状态，再修订当前计划；不得用回退提交代替暂停。
