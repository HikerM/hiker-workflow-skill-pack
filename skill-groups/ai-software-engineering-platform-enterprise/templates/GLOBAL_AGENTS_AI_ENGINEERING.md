# 智能工程性能内核

- 软件工程只自动进入「智能工程轻量路由」。解释、状态查询或不涉及项目动作的简单诊断走快速路径：直接回答，不运行路由脚本、不读取 `.ai`、不扫描仓库。其他插件和 Skill 仅在用户手动选择或轻量路由真实加载时使用。
- 软件工程会话第一条输出为“已应用：01 智能工程核心｜智能工程轻量路由”。原子 Skill 完整读取后、首次实质动作前再显示实际加载的中文插件名与 Skill 名；每阶段最多两个，轻量路由不计入该上限，同阶段不重复。
- ChatGPT 根据当前语义、否定项、未来阶段和有界证据选择原子 Skill；脚本只守门，不按关键词替代选择。已有充分证据时直接一次准入；证据不足才先做一次轻量检查。不得预读全部 Skill、跑全量测试、建图或扫描全仓。
- 最新用户要求和当前 Git 高于 `.ai` 派生状态。无 `.ai` 时无状态推进；`.ai` 缺少可信源码指纹或身份冲突时隔离旧 Task、路由、PASS 与锁，但普通设计、实现、审核和测试继续依据当前请求与 Git 进行。
- 从零项目先融合需求、冲突、未知项和验收，再比较最多三个技术候选；存量项目先建立 `CAP-*` 证据基线再对账 `REQ-*`。B/S、C/S 与服务端技术及版本必须来自工程证据，未知就标记 unknown。
- 用户架构是待验证候选。高影响改动必须检查边界、状态、数据、契约、安全、可靠性、性能、测试、部署和演进；小型改动不增加无关治理。
- 大型或长链路变更用变更契约限制写范围、不变量和最低回归；同一职责只保留一个活动实现，连续两次真实失败后换策略。重要健康变化只显示一次去重中文告警。
- 长会话只注入当前有界工作集；完整事实写入 `.ai` 和 Git。达到软阈值只在自然阶段边界 Checkpoint，达到硬阈值才轮换唯一总控纪元；需求调整修订目标，不为每个 Task 新建总控、会话或 Worktree。
- 只有总控管理桌面任务与 Worktree。写通道按稳定所有权复用，默认最多两个；范围、契约或测试环境重叠时串行。查询失败、脏目录或回收未完成时不得创建替代会话。
- 复杂任务区分业务进展和治理进展；连续两个治理周期没有业务增量就进入首个安全业务切片或报告唯一真实阻断。相同源码、契约、范围和门禁指纹的 PASS 可复用。
- 五插件全量一致性审核只在插件套件收尾执行；普通项目只运行受影响测试分片。完整日志和 diff 写证据文件，会话只接收摘要、路径和指纹。
- 自动应用不扩大权限。未经明确授权不得 push、merge、部署、发布、写生产数据、强制清理 Worktree 或直接修改 main；暂停、调整和恢复必须先保存状态。
