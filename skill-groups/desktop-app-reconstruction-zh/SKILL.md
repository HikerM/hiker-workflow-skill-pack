# 桌面软件等价重建路由

版本：1.3.0

## 边界

只重建已获授权范围内的可观察外部行为。原软件技术指纹与目标实现技术选型必须分开；黑盒证据不得写成源码事实。涉及破解、绕过许可证/登录/DRM、密钥提取、隐蔽监控或未授权资产复制时，停止危险部分并转为合法互操作或原创实现。

重建过程只允许一个当前权威实现和一个当前交付候选。旧原型、旧技术验证、临时兼容层和失败方案必须标记状态、退出条件与清理 Gate，不得继续承载新增需求。正式交付不得默认启用 Demo/Mock/Fixture，不得包含占位数据、样例身份、本机路径、堆栈、数据库或设备内部诊断；证据和模板不得写入用户、公司或真实项目敏感信息。

## 轻量启动

1. 新项目只读取 `references/01_授权与边界.md`；已有项目只读取 `00_control/STATUS.yaml`、`PROJECT.yaml` 和当前门禁状态。
2. 判断本次唯一主阶段，不预加载全部19份参考、全部库存或全部脚本。
3. 只路由一个原子 Skill：
   - G0–G4 证据、页面、交互、功能、数据与覆盖：`desktop-reconstruction-discovery`
   - G5-T 技术候选、POC和精确版本锁定：`desktop-reconstruction-technical-design`
   - G6 独立代码实现：`desktop-reconstruction-implementation`
   - G7–G9 差分、性能、交付与发布：`desktop-reconstruction-verification-release`
4. 用户说“继续”时从状态中的未通过门禁继续，不重做已通过阶段。

## 性能预算

- 单次只读取当前门禁直接需要的状态、参考、库存和证据索引。
- 大型截图、录屏、二进制、源码树和历史证据先建索引，按编号取用，不一次塞入会话。
- 确定性校验交给现有脚本；脚本输出优先使用摘要和失败项，原始报告留在项目目录。
- 不同时启用发现、选型、实现、验证发布四条流程。
- 路由不执行全量观测、全量测试、构建或发布。

## 共同状态与证据

结论等级只使用 `OBSERVED`、`MEASURED`、`INFERRED`、`UNVERIFIED`、`BLOCKED`、`NOT_APPLICABLE`。状态保存在项目 `00_control/`，完整链路为：

```text
范围 → 库存 → 证据 → 规格 → 任务 → 实现 → 测试 → 缺陷/豁免 → 交付物
```

## 路由收据

开始时只显示实际启用的中文 Skill 名称和当前门禁；读取资源与未启用阶段保持在内部状态，不写入应用回执。只有真正跨门禁且当前阶段通过时才切换下一原子 Skill。

## 快捷指令

- “开始新项目 / 盘点材料 / 反推页面 / 检查遗漏” → discovery
- “锁定语言框架和版本 / 做技术POC” → technical-design
- “进入正式实现” → implementation；G0–G5-T未通过则阻断
- “检查是否一致 / 性能对标 / 生成交付包 / 执行全门禁” → verification-release
