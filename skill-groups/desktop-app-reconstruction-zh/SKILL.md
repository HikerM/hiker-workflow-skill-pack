# 桌面软件等价重建

版本：1.1.0  
默认语言：简体中文

## 1. 目标与严格边界

把目标桌面软件的**可观察外部行为**转化为可追踪、可实现、可测试和可交付的独立重建规格。在约定平台、版本、账号、数据和场景范围内验证：

- 视觉、布局、文本、动画和多 DPI 行为；
- 页面状态、交互状态机、快捷键、菜单和系统集成；
- 功能、输入输出、数据持久化、异常、恢复和权限；
- 启动、响应、CPU、内存、GPU、磁盘、网络和长稳；
- 安装、升级、卸载、迁移、回滚和发布物完整性。

不要猜测原软件内部源码。不要把“原软件可能使用的技术”与“重建软件应采用的技术”混为一谈。纯黑盒项目无法证明未暴露的隐藏功能绝对不存在；本 Skill 要保证的是：**已知范围内不存在未登记、未追踪、未测试却被宣布完成的项目，并明确残余未知风险。**

开始前读取 `references/01_授权与边界.md`。遇到破解、绕过许可证/登录/DRM、凭据或密钥提取、隐蔽监控、未授权资产复制、冒充原厂等目标时，停止危险部分，转为合法互操作、原创素材、公开接口兼容或授权迁移方案。

## 2. 运行模式

首次处理项目时明确一种模式：

1. **资料分析**：只有截图、录屏、文档、样例文件或用户描述。输出反推规格、证据缺口、测试与实施任务，不声称已生成正式软件。
2. **代码实施**：存在可读写项目。可探测技术栈、修改源码、运行测试和构建。
3. **自动观测**：存在 Computer Use、桌面自动化或 MCP。可在授权白名单内启动、操作、截图、读取可访问性树和采样性能。
4. **混合模式**：资料、代码和自动观测同时存在。优先用直接观测验证推断，再实施和回归。

没有桌面操作工具时，明确切换到资料分析；不得声称已经点击、录制或测量本机软件。桌面工具存在时读取 `references/09_桌面自动化MCP接口约定.md`。

## 3. 项目启动与会话恢复

### 新项目

1. 识别授权、目标软件版本、目标平台、P0/P1 范围、允许差异和禁止项。
2. 识别当前附件、源码目录、工具权限和可用账号/样例数据。
3. 有文件写入能力时运行：

```bash
python scripts/init_project.py --output <父目录> --project-name "<项目名称>" --source-app "<目标软件>"
```

4. 按 `00_control/PROJECT.yaml`、`STATUS.yaml` 和 `SCOPE_MATRIX.csv` 建立项目事实，不依赖长会话记忆。

### 继续项目

用户说“继续”“进入增强”“进入实现”时，先读取：

- `00_control/PROJECT.yaml`
- `00_control/STATUS.yaml`
- `00_control/DECISIONS.md`
- 当前门禁对应的库存、规格和报告

只从当前未通过门禁继续，不重做已完成阶段，不重复询问已提供信息。会话被用户中断或调整时，先更新 `STATUS.yaml` 的当前动作、已完成项、阻断项和变更原因，再按新指令继续，避免工作流失序。

## 4. 证据与结论等级

所有结论必须使用：

- `OBSERVED`：已直接观察并记录；
- `MEASURED`：已按可重复方法测量；
- `INFERRED`：根据证据推断；
- `UNVERIFIED`：存在说法或需求但无证据；
- `BLOCKED`：因权限、账号、环境、数据或工具受阻；
- `NOT_APPLICABLE`：不适用。

禁止将 `INFERRED`、`UNVERIFIED`、`BLOCKED` 写成“已实现”“完全一致”或“测试通过”。

统一编号：

```text
EV-YYYYMMDD-0001    证据
ENV-0001            环境
ENTRY-0001          入口
WIN-0001 / PAGE-0001
CTRL-0001           控件
INT-0001            交互
FEAT-0001           功能
DATA-0001           数据契约
PERF-0001           性能场景
SPEC-0001           规格
TASK-0001           实施任务
TC-模块-0001        测试
BUG-模块-0001       缺陷
DLV-0001            交付物
WAIVER-0001         豁免
```

## 5. 强制阶段与门禁

完整规则读取 `references/02_阶段流程与门禁.md`。

### G0：授权与范围冻结

产出：`00_control/AUTHORIZATION.md`、`00_control/PROJECT.yaml`、`00_control/SCOPE_MATRIX.csv`；需要豁免时登记到 `07_tests/WAIVERS.csv`。  
通过条件：P0/P1、目标平台、允许差异、禁止操作和资产授权明确。

### G1：环境与证据基线

读取 `references/03_证据采集规范.md`。产出：

- `SOURCE_APPLICATION_PROFILE.yaml`
- `TARGET_CONSTRAINTS.yaml`
- `ENVIRONMENT_MATRIX.csv`
- `PLATFORM_COMPATIBILITY_MATRIX.csv`
- `EVIDENCE_INDEX.csv`、`OBSERVATION_LOG.md`

环境、源软件版本、账号角色、样例数据、分辨率/DPI、硬件、缓存和网络条件必须可追溯；性能比较前必须建立可重复基线。

### G1-T：原软件技术指纹与不确定性边界

读取 `references/13_技术指纹与环境探测规范.md`，产出 `SOURCE_TECH_FINGERPRINT.yaml`。有源码或合法安装目录时先运行：

```bash
python scripts/detect_project_stack.py <源码或安装目录> --json <输出JSON>
```

有源码时，以项目文件、锁文件、CI、构建脚本和实际工具链为直接证据。只有可执行文件时，只能形成带证据、置信度、替代解释和限制的候选指纹；无法证明的精确语言/框架版本保留 `UNKNOWN`。G1-T 的通过含义是“证据和未知边界记录正确”，不是“黑盒情况下已必然识别内部源码技术”。

### G2：入口、窗口、页面、控件与视觉库存

读取 `references/04_UI与交互反推规范.md`。建立：

- `ENTRY_POINT_INVENTORY.csv`
- `WINDOW_PAGE_INVENTORY.csv`
- `INTERACTIVE_CONTROL_INVENTORY.csv`
- `SHORTCUT_MENU_INVENTORY.csv`
- 页面状态矩阵与 `PAGE_SPEC.yaml`

必须覆盖范围内适用的正常、加载、空数据、错误、权限、禁用、悬停、聚焦、选中、编辑、弹窗、最小尺寸、最大化和目标 DPI 状态。每个状态必须明确为已验证、不适用、未验证或受阻，不得留空。

### G3：交互与状态机

每个可交互控件、菜单、快捷键、拖拽、文件关联、托盘和系统入口必须关联 `INT-*`。记录前置条件、触发、处理、状态变化、副作用、成功/失败反馈、取消、超时、撤销、重做和恢复。产出 `INTERACTION_SPEC.yaml`。

### G4-C：功能、数据、权限、异常与覆盖完整性

读取 `references/05_功能与数据反推规范.md` 和 `references/15_覆盖完整性与追踪规范.md`。建立：

- `INTERACTION_INVENTORY.csv`
- `FEATURE_INVENTORY.csv`
- `DATA_CONTRACT_INVENTORY.csv`
- `ROLE_PERMISSION_MATRIX.csv`
- `EXTERNAL_DEPENDENCY_MATRIX.csv`
- `ERROR_RECOVERY_CATALOG.yaml`
- `DISCOVERY_ROUNDS.csv`
- `FEATURE_SPEC.yaml`、`DATA_CONTRACT.yaml`
- `07_tests/PERFORMANCE_SCENARIOS.csv`
- `COVERAGE_MATRIX.csv`、`TRACEABILITY_MATRIX.csv`

发现功能必须交叉使用界面、文档、行为副作用、角色/数据状态、文件/配置、合法接口和异常场景等渠道。P0/P1 在进入正式实现前必须：

- 所有已知入口和可交互控件已登记；
- 具备正常、异常、边界、权限、持久化、重启恢复和中断/回滚覆盖；
- 至少两个独立发现渠道提供证据，或有正式豁免；
- 连续两轮发现检查没有新增 P0/P1 项，或有明确受阻/豁免；
- 不存在范围项无规格、规格无测试等断链。

运行：

```bash
python scripts/validate_discovery.py <项目目录>
python scripts/calculate_coverage.py <项目目录> --phase spec
python scripts/validate_traceability.py <项目目录> --phase spec
python scripts/detect_orphan_items.py <项目目录> --phase spec
```

### G5-T：目标技术选型、精确版本锁定与原型门禁

读取 `references/14_技术栈选型与版本锁定规范.md`。不得写死 C#、C++、Java、Electron、Qt、Unity 或其他路线。流程必须是：

```text
目标约束 → 候选路线 → 官方版本兼容核验 → 代表性 POC → 性能/安装验证 → 决策 → 精确锁定
```

产出：

- `TECH_STACK_CANDIDATES.csv`
- `TECH_STACK_DECISION.yaml`
- `TECH_STACK_LOCK.yaml`
- `OFFICIAL_DOC_INDEX.csv`
- `DEPENDENCY_INVENTORY.csv`
- `TECHNOLOGY_VALIDATION_REPORT.md`

锁定项至少包括：编程语言、运行时、SDK、编译器、UI 框架、构建工具、包管理器、数据库/存储、安装器、目标 OS 与 CPU 架构、第三方依赖和锁文件。禁止使用 `latest`、`stable`、`LTS` 等非精确值作为最终版本。

有网络时，仅优先采集对应**锁定版本**的官方文档，并记录版本、检索日期、适用平台、章节和状态；无法找到时标记风险，不能通过 G5-T。代表性 POC 至少验证一个复杂核心页面、文件/数据操作、DPI、安装包、冷启动和内存。

运行：

```bash
python scripts/validate_toolchain.py <项目目录>
```

未通过 G5-T，不得开始大规模正式编码。

### G6：独立实现

仅在可写代码工作区执行。每项代码必须关联规格、任务和测试编号。优先真实端到端闭环，不得用静态页面、假接口、固定成功值或演示数据冒充完成。表现、应用、领域、基础设施、集成和平台层解耦；长任务支持进度、取消、超时、错误码和恢复。每轮更新 `STATUS.yaml`、`CHANGELOG.md`、追踪矩阵和测试结果。

### G7：视觉、功能和数据差分验证

原软件与候选软件使用同一环境、账号、数据和操作脚本。比较截图、控件状态、文本、文件、数据库、配置、日志、错误、重启状态和输出。像素差异只是证据之一，必须结合区域几何、动态遮罩、文本/控件检查和人工复核。

### G8：性能与稳定性

读取 `references/07_性能稳定性规范.md`。性能场景必须关联 `FEAT-*`，保留原始样本和环境。至少覆盖冷/热启动、首屏可交互、核心操作 P50/P95/P99、资源占用、大数据、异常恢复、内存增长、崩溃和项目约定长稳。性能优化后重新执行功能与视觉回归。

### G9-D：打包、交付物完整性和发布门禁

读取 `references/16_交付物完整性规范.md`。根据当前模式建立 `DELIVERABLE_MANIFEST.yaml`，明确每个产物为必需、条件必需或不适用，并记录路径、版本、状态、校验值和证据。运行：

```bash
python scripts/validate_deliverables.py <项目目录> --phase release --write-checksums
python scripts/run_quality_gates.py <项目目录> --phase release --write-checksums
```

只有结构、工具链、追踪、覆盖、孤立项、性能、缺陷和交付物门禁全部满足，才可签发 `RELEASE_READINESS_REPORT.md`。

## 6. 编程语言和版本的硬规则

1. **原软件技术指纹**与**目标实现技术栈**分开记录。
2. 有源码：从清单、项目文件、锁文件、CI、编译脚本和工具链文件识别精确版本。
3. 只有二进制：只输出候选技术、证据和置信度；不能保证内部语言精确版本。
4. 目标技术不以“像原软件”作为唯一依据，必须满足目标 OS、架构、性能、GPU、多媒体、系统集成、离线、安装、维护和许可约束。
5. 正式编码前必须有真实 POC、安装验证和精确版本锁定。
6. 锁文件、依赖哈希、构建命令、编译参数和官方文档索引必须可复核。
7. 目标平台或最低系统版本改变时，重新执行 G5-T，不能沿用旧结论。

## 7. 无遗漏与追踪硬规则

完整链路：

```text
范围 → 入口/库存 → 证据 → 规格 → 实施任务 → 源码/配置 → 测试 → 结果 → 缺陷/豁免 → 交付物
```

自动检查并阻断：

- 范围项无库存；
- 入口、页面、控件或功能无证据/规格；
- 规格无实施或测试；
- 实施无需求来源；
- 测试无实际结果；
- 失败测试无缺陷；
- 已关闭缺陷无回归证据；
- P0/P1 使用未批准豁免；
- 测试、证据、规格或实现存在孤立项；
- 交付物清单声称存在但文件缺失或校验不一致。

P0/P1 的追踪链必须 100% 完整且测试通过。P2/P3 按冻结阈值或正式豁免。最终报告必须包含 `RESIDUAL_UNKNOWN_RISK_REPORT.md`，不得用“未发现问题”替代“证明没有问题”。

## 8. 软件反推重建的输出

### 资料分析模式

输出授权/范围、证据库、环境与技术指纹、入口/页面/控件/功能库存、视觉/交互/功能/数据/性能规格、技术候选、缺口、风险、测试计划和 Codex 任务包。不得输出“安装包已完成”。

### 代码实施模式

在上述基础上输出正式源码、资源、配置、迁移、接口适配、依赖锁、自动化测试、构建脚本、安装/升级/卸载和工程文档。

### 自动观测或混合模式

额外输出操作重放、控件树快照、基准截图/录屏、文件与配置差分、性能原始采样、自动差分和长稳记录。

最终交付始终分为：反推证据、软件规格、技术方案、实现成果、发布成果、验收成果。完整目录见 `references/11_输出协议.md`。

## 9. 工具与脚本规则

只在确定性处理时运行脚本。脚本不得替代工程判断。

- `init_project.py`：创建 v1.1 标准项目；
- `index_evidence.py`：证据索引与 SHA-256；
- `detect_project_stack.py`：只读识别源码技术栈和版本证据；
- `validate_toolchain.py`：检查精确版本、POC、平台、官方文档和锁文件；
- `validate_discovery.py`：检查独立发现渠道和连续无新增核心项；
- `calculate_coverage.py`：计算库存、测试和追踪覆盖；
- `validate_traceability.py`：验证 ID 与端到端链路；
- `detect_orphan_items.py`：发现未关联项目；
- `compare_screenshots.py`：基础截图差异；
- `validate_deliverables.py`：检查交付物、状态和校验值；
- `run_quality_gates.py`：汇总门禁；
- `validate_project.py`：基础结构和占位符检查；
- `validate_skill_package.py`、`self_test.py`：Skill 包和回归自检；
- `install_skill.py`：用户级或项目级安全安装。

脚本失败时保留报告，修复真实问题；不得删除检查项或修改门禁数据来制造通过。

## 10. 每轮回复格式

除极短问答外，使用：

```text
1. 本轮完成
2. 证据与结论等级
3. 新增或修改文件
4. 门禁结果：PASS / CONDITIONAL / FAIL / NOT_RUN
5. 未验证、受阻和残余风险
6. 下一步唯一主动作
```

长任务每完成一个门禁就报告真实产物。能继续时直接继续；只在缺少真正阻断信息时提出少量问题。

## 11. 完成用词门禁

只有同时满足下列条件，才可写“达到约定范围内等价”或“验收通过”：

- 范围和版本已冻结；
- G1-T、G4-C、G5-T、G9-D 通过；
- P0/P1 追踪链和测试 100% 通过；
- 关键视觉、数据、性能、长稳、安装、升级、卸载和迁移通过；
- P0/P1 缺陷为零；
- 所有 `UNVERIFIED`、`BLOCKED` 和豁免已在范围内接受；
- `DELIVERABLE_MANIFEST.yaml` 校验通过。

不得承诺未观察的隐藏规则、未测试硬件或未取得权限的角色达到 100% 一致。

## 12. 中文快捷指令

- “开始新项目”——执行 G0 并初始化目录。
- “盘点现有材料”——执行证据、环境和缺口盘点。
- “自动识别工程技术栈”——运行技术栈探测并生成指纹。
- “锁定编程语言和版本”——执行 G5-T，不直接选最新版本。
- “反推这个页面/功能”——生成库存、规格和测试。
- “检查功能有没有遗漏”——执行发现饱和、覆盖、追踪和孤立项审计。
- “生成追踪矩阵”——更新 `TRACEABILITY_MATRIX.csv`。
- “进入正式实现”——仅在 G0-G5-T 通过后执行。
- “检查是不是一模一样”——执行视觉、功能、数据和性能差分。
- “执行全门禁”——运行 `run_quality_gates.py`。
- “生成完整交付包”——按 `DELIVERABLE_MANIFEST.yaml` 生成并校验。
- “继续”——从 `STATUS.yaml` 的唯一主动作继续。
