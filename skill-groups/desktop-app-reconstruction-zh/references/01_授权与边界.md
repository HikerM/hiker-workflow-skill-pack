# 01 授权与边界规范

## 1. 允许的典型场景

- 用户拥有目标软件、源码或相关资产；
- 用户代表权利人，或获得客户/权利人的书面授权；
- 企业内部旧系统迁移、国产化替代、跨平台迁移；
- 为文件格式、公开协议、设备或业务流程进行合法互操作；
- 基于外部可观察行为和自有素材进行 clean-room 独立实现；
- 对自有软件进行重构、测试补全、技术栈升级或性能优化。

## 2. 必须停止或转向的场景

不得协助：

- 绕过许可证、激活、DRM、登录、支付、配额或安全控制；
- 导出、猜测或窃取密钥、凭据、令牌、个人数据和商业机密；
- 未经许可复制原软件源码、商标、图标、字体、图片、音频、视频、模型或训练数据；
- 隐蔽键盘记录、屏幕监控、数据外传、进程注入或恶意持久化；
- 将重建软件冒充原厂产品或制造来源混淆；
- 绕过第三方服务的计费、授权或访问限制。

遇到上述目标时，停止危险部分，转为原创设计、公开接口兼容、合法数据迁移、授权测试或高层方案。

## 3. Clean-room 建议

1. 观察与实现职责分离；
2. 观察侧只记录外部行为、输入、输出、环境和证据；
3. 实现侧依据冻结规格独立设计内部架构；
4. 受保护素材使用自有、授权或原创替代品；
5. 关键授权、第三方许可和发布品牌由项目方审查；
6. 对外发布前进行知识产权、隐私和许可证审核。

## 4. AUTHORIZATION.md 最低内容

- 项目、目标软件、版本和权利主体；
- 用户身份或授权来源及文件位置；
- 允许观察、测试、迁移、网络时序、文件监控、控件树和性能采集的范围；
- 允许使用的账号、数据、设备和环境；
- 禁止触碰的系统、目录、账号和资产；
- 是否允许桌面自动化及破坏性动作；
- 脱敏和保留期限；
- 授权有效期、确认人和日期。

Skill 不是法律意见。授权不明确时，只做高层兼容方案、原创重设计和风险清单。
