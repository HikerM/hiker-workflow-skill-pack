# 02 阶段流程与门禁

| 阶段 | 目标 | 必需输出 | 阻断条件 |
|---|---|---|---|
| G0 | 授权与范围冻结 | AUTHORIZATION、PROJECT、SCOPE、WAIVERS | P0/P1 或禁止项不明确 |
| G1 | 环境与证据基线 | 环境矩阵、源应用档案、目标约束、证据索引 | 环境、版本、账号、数据或基线无来源 |
| G1-T | 原软件技术指纹 | 技术指纹、直接事实、候选、置信度和未知边界 | 黑盒推断冒充精确语言/版本事实 |
| G2 | 入口、窗口、页面、控件 | 入口/页面/控件库存、页面规格、状态矩阵 | 核心入口或适用状态未登记 |
| G3 | 交互状态机 | 交互规格、快捷键、菜单和恢复行为 | 只记录跳转，不记录结果/异常 |
| G4-C | 功能、数据、权限、覆盖 | 功能/权限/依赖/错误库存、发现轮次、覆盖和追踪 | P0/P1 断链或发现未饱和 |
| G5-T | 技术候选、POC、精确版本 | 候选、决策、锁文件、官方文档、POC 报告 | 版本浮动、POC/平台/文档未通过 |
| G6 | 独立实现 | 正式源码、任务、测试、构建配置 | 假接口、演示数据、无规格关联 |
| G7 | 视觉/功能/数据差分 | 一致性报告、缺陷、回归证据 | P0/P1 差异未关闭 |
| G8 | 性能和稳定性 | 原始样本、性能/长稳报告 | 环境不可比或门禁未达标 |
| G9-D | 打包、交付、发布 | 安装/升级/卸载、交付清单、发布报告 | 必需交付物缺失或校验失败 |

## 1. 门禁状态

- `NOT_RUN`：未执行；
- `IN_PROGRESS`：进行中；
- `PASS`：全部通过；
- `CONDITIONAL`：仅非阻断项有条件接受；
- `FAIL`：存在阻断失败；
- `BLOCKED`：缺少环境、账号、数据或工具；
- `NOT_APPLICABLE`：经范围判断不适用。

P0/P1 门禁不得用 `CONDITIONAL` 代替 `PASS` 进入发布，除非有正式豁免且项目范围明确允许。

## 2. 阶段依赖

```text
G0 → G1 → G1-T → G2/G3 → G4-C → G5-T → G6 → G7/G8 → G9-D
```

允许 G2、G3、G4 的不同模块并行，但公共 ID、数据契约、导航和范围必须先冻结。G5-T 未通过前只允许 POC，不允许大规模正式实现。

## 3. 每阶段结束必须更新

- `00_control/STATUS.yaml`；
- `00_control/DECISIONS.md`；
- `00_control/CHANGELOG.md`；
- 对应库存、证据、追踪和测试结果；
- 当前门禁报告与唯一主动作。

## 4. 禁止制造通过

- 用页面截图替代功能完成；
- 用一次成功操作替代稳定性；
- 在不可比环境中声称性能相同；
- 删除失败、边界和恢复测试；
- 临时降低优先级或门禁阈值；
- 将 `BLOCKED` 改成 `NOT_APPLICABLE`；
- 在清单中填写不存在的文件、测试和实现路径。

## 5. 中断与调整

用户可以在执行中随时中断、修改范围或路线。处理顺序：

1. 记录已完成产物和当前安全状态；
2. 将未完成动作标为暂停，不伪造完成；
3. 在 `DECISIONS.md` 记录范围/路线变化；
4. 重新计算受影响门禁和追踪链；
5. 从新主动作继续，不要求每一步人工确认。
