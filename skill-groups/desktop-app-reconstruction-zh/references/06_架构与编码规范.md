# 06 架构、实施与编码规范

## 1. 选型前置

技术路线由 `TARGET_CONSTRAINTS.yaml`、候选评分、官方兼容资料和 POC 决定。不得从本文件的候选表直接选定语言。

| 特征 | 可能候选，仅供生成候选 |
|---|---|
| Windows 表单、系统集成 | .NET 原生路线、Qt、原生 C++ |
| 多平台业务工具 | Qt、Tauri、成熟跨平台框架 |
| Web 团队、复杂后台式 UI | Electron、Tauri |
| 3D、仿真、实时动画 | Unity、专业图形引擎 |
| 视频、图像、CAD、专业工具 | Qt/原生 + GPU/媒体模块 |

实际版本必须通过 G5-T。

## 2. 最低分层

```text
Presentation      窗口、页面、控件、交互绑定
Application       用例编排、权限、事务、任务和取消
Domain            业务规则、状态机、模型和不变量
Infrastructure    数据库、文件、缓存、网络和日志
Integrations      第三方 SDK、服务、设备和格式适配
Platform          OS、窗口、托盘、通知、更新和安装
Tests             单元、集成、契约、UI、性能和打包
```

## 3. 强制规则

- 页面不得直接操作数据库、文件或远程服务；
- UI 状态与领域状态分离；
- 禁止无边界全局状态和内存缓存；
- 禁止写死账号、路径、服务器、业务数据和成功结果；
- 禁止用假接口、静态页面或通用占位图冒充正式实现；
- 外部依赖经接口/适配层，支持替换和测试替身；
- 文件写入考虑原子性、锁、备份、校验和恢复；
- 长任务可取消、有进度、超时、错误码和安全恢复；
- 配置、缓存、日志、临时文件和正式数据分目录；
- 数据升级有迁移、备份和回滚；
- 依赖版本锁定，构建命令可重复；
- 核心模块有自动化测试和可观测日志；
- 性能优化不得破坏功能、视觉、数据和可维护性。

## 4. 端到端优先

先实现一条真实闭环：入口 → UI → 应用用例 → 数据/服务 → 成功/失败反馈 → 持久化 → 重启 → 测试。闭环通过后再扩展页面和模块，避免先生成大量无法验证的壳。

## 5. 任务格式

每个任务必须包含：

- TASK ID、标题、目标和优先级；
- 关联范围、库存、证据和规格；
- 输入、依赖和前置门禁；
- 修改文件和禁止修改范围；
- 数据迁移或兼容影响；
- 验收条件和测试命令；
- 性能/安全影响；
- 证据产物和回滚点。

## 6. 多代理与 Git

- 一个任务对应一个分支或隔离 worktree；
- 公共契约先冻结再并行；
- 每个代理只修改声明范围；
- 合并前运行追踪、测试和构建门禁；
- 禁止多个副本在无分支标识下同时作为“最新版本”；
- `STATUS.yaml` 记录当前权威分支、提交和构建版本。
