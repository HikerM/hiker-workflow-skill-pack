# 08 视觉、功能、数据与发布一致性验收

## 1. 视觉

检查窗口结构、区域、控件几何、文本、状态、图标语义、颜色、边框、阴影、间距、动画、多分辨率和 DPI。

组合方法：

```text
基础像素差异
+ 关键区域几何
+ 文本/控件树
+ 动态遮罩
+ 动画时序
+ 人工复核
```

动态时间、用户名、随机内容和第三方内容先遮罩，不用扩大整体容差掩盖错误。

## 2. 功能

- P0：100% 设计、执行、通过；
- P1：100% 设计、执行、通过；
- P2/P3：按冻结阈值或批准豁免；
- 同一输入应得到相同或已接受的等价输出；
- 正常、异常、边界、权限、持久化、恢复和大数据场景必须有结果。

## 3. 数据

比较文件、数据库、缓存、配置、日志、接口和重启状态。检查事务、回滚、迁移、编码、时区、排序、精度、幂等和损坏恢复。

## 4. 性能

按冻结绝对值和相对原软件比值判断。原始样本、环境和统计方法必须可复核，不能临时放宽门禁。

## 5. 缺陷

- `P0 Blocker`：启动/数据/安全/核心流程/发布阻断；
- `P1 Critical`：核心功能、关键视觉或明显性能退化；
- `P2 Major`：一般功能或局部重大差异；
- `P3 Minor`：低影响细节。

失败测试必须关联缺陷。缺陷关闭必须有关联回归测试为 `PASS`。

## 6. 报告状态

- `PASS`；
- `CONDITIONAL`；
- `FAIL`；
- `NOT_RUN`；
- `BLOCKED`；
- `NOT_APPLICABLE`；
- `WAIVED`。

“未发现问题”不等于“证明没有问题”。

## 7. 发布条件

- 范围冻结；
- G4-C、G5-T、G9-D 通过；
- P0/P1 测试 100% 通过；
- 关键视觉、数据、性能和长稳通过；
- 安装、升级、卸载、迁移和回滚通过；
- P0/P1 缺陷为零；
- 豁免包含原因、影响、批准和有效期；
- 残余未知风险被明确接受；
- 交付物清单校验通过。
