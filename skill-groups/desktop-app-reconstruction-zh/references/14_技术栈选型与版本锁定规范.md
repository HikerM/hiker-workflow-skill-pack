# 14 技术栈选型与精确版本锁定规范

## 1. 目标

确保重建软件使用的编程语言、运行时、框架、SDK、编译器和依赖是由项目约束和实测结果决定，并锁定到可重复构建的精确版本。

## 2. 禁止直接选型

不得仅根据以下理由直接决定技术路线：

- 原软件“看起来像”某框架；
- 某技术当前流行；
- 选择“最新版”“稳定版”或“LTS”但不写精确版本；
- 团队只熟悉一种语言而不验证目标平台；
- 只做静态页面 POC，没有文件、数据、安装和性能；
- 只根据框架官网宣称支持，不做目标硬件和系统实测。

## 3. 目标约束清单

`TARGET_CONSTRAINTS.yaml` 至少冻结：

- 目标 OS、最低版本、补丁和 CPU 架构；
- 分辨率、DPI、多显示器和输入设备；
- 是否离线、是否有本地服务或远程服务；
- 文件、数据库、打印、串口、USB、托盘、通知、自动更新和权限要求；
- 3D、视频、图像、音频、GPU 和实时性要求；
- 冷启动、响应、内存、包体和长稳门禁；
- 安装、升级、卸载、回滚和签名要求；
- 团队能力、维护周期、供应链和许可证限制。

## 4. 候选生成与评分

每个候选写入 `TECH_STACK_CANDIDATES.csv`，至少评分：

| 维度 | 说明 |
|---|---|
| 平台兼容 | 目标 OS、架构和最低版本是否官方支持 |
| UI 还原 | 原生控件、自绘、字体、DPI、动画和可访问性 |
| 性能 | 启动、内存、CPU/GPU、I/O 和大数据能力 |
| 系统集成 | 文件关联、托盘、通知、打印、设备、服务和更新 |
| 打包发布 | 安装器、签名、升级、离线依赖和回滚 |
| 可维护性 | 生态、支持周期、调试、测试和人员供给 |
| 团队匹配 | 当前团队能否长期维护 |
| 许可与供应链 | 框架和依赖许可、来源、SBOM 和漏洞维护 |

权重写入项目决策，不得在结果出来后为了偏向某候选临时改权重。

## 5. 官方兼容核验

有网络能力时，优先查对应版本的官方文档和发布说明。每项记录到 `OFFICIAL_DOC_INDEX.csv`：

- component_id；
- 组件名称；
- 锁定版本；
- 官方来源标题；
- 文档版本；
- 获取日期；
- 支持的 OS/架构；
- 关键章节；
- 核验状态；
- 风险和证据。

规则：

1. 文档版本必须与锁定版本一致或明确覆盖该版本。
2. 不用最新版文档替代旧版本行为。
3. 官方文档缺失时，可补充官方源码仓库、标准或供应商支持声明，并标记风险。
4. 文档声明与实际 POC 冲突时，保留冲突记录，以可重复实测和目标环境为准。
5. 无法核验目标平台时，G5-T 不通过。

## 6. 代表性 POC

每个进入决选的候选至少实现：

- 主窗口启动与关闭；
- 一个复杂核心页面，包含真实布局、表格/列表、弹窗和状态切换；
- 文件或数据库读写；
- 一个关键外部依赖或系统集成；
- 100%、125%、150% 等目标 DPI；
- 目标最低 OS/架构构建；
- 安装、启动、卸载；
- 冷启动、首屏可交互、空闲和峰值内存测量；
- 失败路径和日志。

静态截图、假数据和未打包运行不能算 POC 通过。

## 7. 精确版本锁定

`TECH_STACK_LOCK.yaml` 的必需组件不得使用：

```text
UNKNOWN
UNDECIDED
latest
stable
LTS
x
*
>=
^ 或 ~ 范围（作为最终锁定值）
```

至少锁定：

- 编程语言；
- 运行时；
- SDK；
- 编译器；
- UI 框架；
- 构建工具；
- 包管理器；
- 数据库或存储引擎；
- 安装器；
- 关键第三方 SDK；
- 目标 OS、架构和构建模式。

每个必需组件必须有：名称、精确版本、验证来源、是否已安装验证、官方文档记录和支持平台。

## 8. 依赖锁与供应链

- JavaScript、Rust、Python、.NET、Java、Go 等使用对应锁文件或解析后的不可变依赖清单；
- 禁止构建时无约束下载浮动版本；
- 记录直接和传递依赖、许可证、来源和哈希；
- 生成 SBOM 或至少依赖清单；
- 关键依赖不可获得时必须有镜像、离线包或替代方案；
- 版本升级必须重新执行兼容、视觉、功能和性能回归。

## 9. 构建可重复性

至少验证：

1. 全新环境按照文档可安装工具链；
2. 连续两次干净构建均成功；
3. 构建命令、环境变量、依赖源和编译参数有记录；
4. 产物版本、文件清单和 SHA-256 可追踪；
5. 若因时间戳/签名导致二进制哈希不同，记录可解释差异；
6. 不依赖开发者机器上的未声明全局组件。

## 10. G5-T 通过条件

- 目标约束已冻结；
- 至少两个合理候选完成比较，或单候选有充分排他理由；
- 选中候选的代表性 POC 为 `PASS`；
- 必需工具链和依赖精确版本全部锁定；
- 必需平台兼容行均为 `PASS`；
- 官方文档索引覆盖必需组件；
- 依赖锁文件存在且无浮动版本；
- `validate_toolchain.py` 返回 0；
- 技术负责人接受决策和回滚条件。
