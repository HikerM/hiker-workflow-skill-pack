# 16 交付物完整性与发布门禁规范

## 1. 交付不是一个 ZIP

正式交付分为：反推证据、软件规格、技术方案、实现成果、发布成果和验收成果。一个安装包、一个源码目录或一份报告都不能单独代表项目完整交付。

## 2. 按运行模式决定必需项

- **资料分析**：源码、安装包和构建产物可按规则判定为不适用，但证据、库存、规格、技术方案、测试设计、覆盖和风险报告必须完成。
- **代码实施**：源码、实现索引、依赖锁、自动化测试、构建脚本和工程文档为必需；安装包是否进入当前阶段由范围和阶段决定。
- **自动观测**：操作脚本、处理证据、控件树、基准截图和采样数据为必需。
- **发布交付**：安装、升级、卸载、迁移、回滚、校验、SBOM、许可证和发布报告均为必需。

工具、账号、环境或时间不足时，应标记 `BLOCKED` 或 `MISSING`，不能把本应必需的项目改成 `NOT_APPLICABLE`。

## 3. 两层清单

### `DELIVERABLE_CHECKLIST.csv`

这是规范层，定义：

```text
deliverable_id,path,kind,required_for_mode,stage,
min_size_bytes,min_non_placeholder_items,placeholder_forbidden,
forbidden_markers,required_markers,checksum_required,notes
```

### `DELIVERABLE_MANIFEST.yaml`

这是项目实例层，由 `init_project.py` 根据检查表逐项生成。每项至少包含：

```yaml
- id: "DLV-0001"
  path: "00_control/PROJECT.yaml"
  kind: "file"
  required_modes: ["all"]
  stage: "G0"
  status: "READY"
  version: "1.1.0"
  sha256: "..."
  checksum_required: false
  related_ids: ["SC-0001"]
  evidence_ids: []
  waiver_id: ""
  owner: ""
  notes: ""
```

清单顶层应包含：

```yaml
schema_version: "1.1"
project_id: "PROJECT-ID"
execution_mode: "analysis"
manifest_status: "VERIFIED"
generated_from: "00_control/DELIVERABLE_CHECKLIST.csv"
items: []
```

## 4. 状态语义

- `READY`：文件/目录存在、内容完成并通过当前规则；
- `DRAFT`：存在但未完成；
- `MISSING`：缺失；
- `BLOCKED`：因明确条件受阻；
- `NOT_APPLICABLE`：经模式、阶段和范围规则判定不适用；
- `SUPERSEDED`：已被新版本替代。

`manifest_status: VERIFIED` 只能在当前所有必需项通过后写入。

## 5. 文件级校验

- 路径必须位于项目根目录内，禁止绝对路径和路径穿越；
- 必需项必须是普通文件或明确允许的目录；
- `.gitkeep`、`.keep` 和 `*.example.*` 不计作正式目录内容；
- 文件存在不等于完成，正文不能只有模板占位符、空表或禁止标记；
- `READY` 且要求校验值的项目必须记录 SHA-256；
- 校验值不一致视为失败；
- 构建产物应关联版本、构建日志、源码提交或快照；
- 安装包、升级包、便携包和回滚包分别验证，不得互相替代。

## 6. 发布验证

至少覆盖：

- 全新机器安装；
- 覆盖升级和跨版本迁移；
- 卸载及用户数据保留策略；
- 安装失败回滚；
- 配置、缓存、日志和数据目录；
- 权限、签名、杀毒误报和依赖缺失；
- 离线或代理环境；
- 所有目标 OS 和 CPU 架构；
- 安装后核心冒烟；
- 卸载后残留清单。

## 7. 文档交付

最低包括安装、用户、管理员、开发维护、数据迁移、故障恢复、升级回滚、第三方依赖与许可证、交付验收九份文档。命令、路径和版本必须与实际产物一致。

## 8. 校验命令

```bash
python scripts/validate_deliverables.py <项目目录> \
  --mode analysis|implementation|automation|mixed \
  --phase spec|implementation|release \
  [--write-checksums]
```

脚本同时检查规范清单和实例清单，包括语法、重复 ID、模式/阶段、文件存在、最小内容、占位符、标记、路径安全、状态与 SHA-256。

## 9. G9-D 通过条件

- 当前模式和阶段的所有必需项均为 `READY`；
- 要求的 SHA-256 与实际文件一致；
- 无模板占位符、空报告、伪造路径或用示例文件冒充正式内容；
- 安装、升级、卸载、迁移和回滚按范围通过；
- SBOM 和许可证清单完成；
- 追踪矩阵可关联到交付物；
- 聚合门禁返回 `PASS`；
- `RELEASE_READINESS_REPORT.md` 与机器检查和人工审查一致。
