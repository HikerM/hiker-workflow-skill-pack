# 17 会话中断与状态恢复

## 1. 目标

允许用户在长任务中随时调整方向，同时避免每一步停下询问、上下文压缩丢失信息、多个会话或工作区相互覆盖。

## 2. 状态文件优先于聊天记忆

项目事实写入：

```text
00_control/PROJECT.yaml
00_control/STATUS.yaml
00_control/DECISIONS.md
00_control/CHANGELOG.md
07_tests/TRACEABILITY_MATRIX.csv
```

聊天只用于本轮决策和说明。恢复时不依赖完整历史对话。

## 3. 检查点

在以下时机更新 `STATUS.yaml`：

- 阶段或子门禁开始/结束；
- 执行可能耗时或批量修改前；
- 用户中断或改变要求；
- 即将发生上下文压缩；
- 切换会话、工作区、分支或执行者；
- 合并或发布前。

检查点至少包括当前门禁、完成项、进行项、阻断项、下一主动作、允许修改路径、基线版本和恢复命令。

## 4. 用户中断处理

1. 停止尚未开始的后续动作；
2. 不自动回滚已通过且与新要求无冲突的成果；
3. 记录新决策和影响范围；
4. 把受影响项状态改为 `REVIEW_REQUIRED`；
5. 从最早受影响门禁继续；
6. 不反复询问已经明确的信息。

## 5. 多会话和多工作区

每个工作单元记录：

```text
work_unit_id
session_or_agent
base_revision
branch_or_worktree
allowed_paths
owned_spec_ids
owned_test_ids
merge_order
status
```

禁止多个工作单元无协调修改：公共契约、数据库迁移序列、版本文件、锁文件和发布配置。

## 6. Git 或无 Git 项目

### 有 Git

- 每个并行单元使用独立分支或 worktree；
- 合并前先更新基线并运行对应测试；
- 版本号、迁移号和锁文件由指定集成单元维护；
- `STATUS.yaml` 记录提交 ID。

### 无 Git

- 修改前创建时间戳备份；
- 每个工作单元使用独立副本，不直接共写；
- 使用 `CHANGELOG.md` 和文件哈希记录变化；
- 由单一集成目录接受合并。

## 7. 上下文压缩恢复

恢复顺序：

1. STATUS；
2. PROJECT；
3. 最新 DECISIONS 和 CHANGELOG；
4. 当前门禁关联范围/规格/测试；
5. 仅在证据不足时读取对应原始证据。

不要一次加载全部截图、录屏、源码和历史报告。
