# 18 ID、状态和字段规范

## 1. ID 唯一性

ID 在整个项目内全局唯一。禁止复用已删除 ID；删除项改为 `SUPERSEDED` 或在变更日志记录。

| 类型 | 格式 |
|---|---|
| 范围 | `SC-0001` |
| 环境 | `ENV-0001` |
| 证据 | `EV-YYYYMMDD-0001` |
| 发现轮次 | `DISC-0001` |
| 入口 | `ENTRY-0001` |
| 窗口 | `WIN-0001` |
| 页面 | `PAGE-0001` |
| 控件 | `CTRL-0001` |
| 交互 | `INT-0001` |
| 功能 | `FEAT-0001` |
| 数据 | `DATA-0001` |
| 权限 | `PERM-0001` |
| 错误 | `ERR-0001` |
| 性能 | `PERF-0001` |
| 规格 | `SPEC-0001` |
| 任务 | `TASK-0001` |
| 测试 | `TC-模块-0001` |
| 缺陷 | `BUG-模块-0001` |
| 豁免 | `WAIVER-0001` |
| 交付物 | `DLV-0001` |
| 架构决策 | `ADR-0001` |

## 2. 多 ID 字段

CSV 中多个 ID 使用分号 `;` 分隔，不使用自然语言连接。例如：

```text
EV-20260801-0001;EV-20260801-0002
```

脚本同时兼容逗号和竖线，但写回时统一分号。

## 3. 状态

### 证据/规格状态

`OBSERVED`、`MEASURED`、`INFERRED`、`UNVERIFIED`、`BLOCKED`、`NOT_APPLICABLE`。

### 工作状态

`NOT_STARTED`、`IN_PROGRESS`、`READY_FOR_REVIEW`、`PASS`、`CONDITIONAL`、`FAIL`、`BLOCKED`、`SUPERSEDED`。

### 测试状态

`NOT_RUN`、`PASS`、`FAIL`、`BLOCKED`、`SKIPPED_WITH_WAIVER`。

### 缺陷状态

`OPEN`、`IN_PROGRESS`、`FIXED`、`VERIFIED`、`CLOSED`、`WONT_FIX_WITH_WAIVER`。

## 4. 优先级

- `P0`：启动、数据损坏、安全、核心流程或发布阻断；
- `P1`：核心功能、关键视觉、关键性能；
- `P2`：一般功能和局部重大差异；
- `P3`：低频辅助和小型细节。

优先级变更必须写入 `DECISIONS.md`，不能仅改 CSV。

## 5. 布尔值

CSV 统一使用小写 `true` / `false`。YAML 使用标准布尔值，不使用“是/否”作为机器字段。

## 6. 时间与版本

- 时间使用 ISO 8601，包含时区；
- 日期使用 `YYYY-MM-DD`；
- 软件版本使用实际版本字符串；
- 未知写 `UNKNOWN`，尚未决定写 `UNDECIDED`；
- 最终技术锁禁止 `UNKNOWN`、`UNDECIDED` 和浮动范围。

## 7. 路径

项目内路径使用相对 POSIX 形式，例如：

```text
04_specifications/features/FEAT-0001.yaml
```

不得在交付清单中写开发者机器绝对路径。
